# 剪辑工作台 · 开始在这里

一句话：**把视频丢进 `输入` 文件夹，回 WorkBuddy 说一句「用口播出稿，跑一下输入」，AI 引导推进，剪映里就出现草稿。**（别直接双击 `工具\剪辑.cmd`——没有 AI 在场，没人审错误、没人盯闸口。）

> 🤖 **agent 必读**：由 AI 推进工序的，动手前先读 [`说明书\AGENT运行守则.md`](说明书/AGENT运行守则.md) ——
> 宿主环境命令照抄（cmd/PowerShell/coreutils 都有坑）、六闸口裁决脚手架直接复用、
> 已修死的 bug 清单（登记草稿箱 / VFR 帧率 / 幻词 / 配图重叠），读完能省一半往返。

## 0. 先搞清"你是谁、你在哪"

如果你是从分发包装的，这个文件夹就在 **WorkBuddy 工作区的根目录**下，
Skill 本体是工作区里的项目级技能：

```
口播视频剪映出草稿-xgz-win-workbuddy-完整版\           ← 用 WorkBuddy「打开文件夹」选的就是这层
├─ README.md           ← 快速上手（3 步装好）
├─ .workbuddy\skills\kbcg-xgz-win-workbuddy\
│   ├─ SKILL.md         ← 工序宪法（二十个阶段、六个决策闸口，以 SKILL.md 为准）
│   ├─ 脚本\ 脚本_win\   ← 真正干活的契约脚本
│   └─ 部署\            ← 安装与自检（bootstrap.cmd）
└─ 剪辑工作台\           ← 你在这里
```

**两种用法，同一套东西**（不是两个版本，可以来回切）：

| 用法 | 谁在跑 | 怎么起 |
|---|---|---|
| **对话式（推荐）** | WorkBuddy 里的 AI，按 `SKILL.md` 逐步走，边跑边审错 | 说一句「用口播出稿，把这条剪一下」 |
| **丢素材就跑** | 同一套状态机，机械步骤全自动；判断闸口仍由 AI 写 JSON | 视频丢 `输入\`，对话里说「用口播出稿，跑一下输入」 |

> **衔接点**：本工作台只是把 `SKILL.md` 的工序排成了状态机。所以
> **工序定义、字段要求、失败条件一律以 `SKILL.md` 为准**；两边共用同一个
> `工作区\<片名>\`，产物互相认识。
>
> 你不用管这个差别——**跑到该做判断的地方它会停下来告诉你**。

## 1. 目录地图

| 文件夹 / 文件 | 干什么 | 你要不要动 |
|---|---|---|
| `输入\` | 放原素材，**按天建日期文件夹**（`输入\2026-09-15\`） | ✅ **只动这里** |

## 2. 标准操作流程

### 第一步 · 丢素材

在 `输入\` 下建一个**当天日期的文件夹**，视频丢进去：

```
输入\2026-09-15\晨跑怎么坚持.mp4
```

一期有多个文件时，再在日期文件夹里套一层：

```
输入\2026-09-15\晨跑怎么坚持\原片.mp4
```

直接丢在 `输入\` 根下也能接单（程序会提醒挪进去），但**统一按天建文件夹**，日子多了才翻得动。

**片名和「核心表达」默认取文件名**，所以文件名就用中文核心表达：

```
晨跑怎么坚持.mp4  →  成片 2026-09-14_晨跑怎么坚持_剪映草稿
```

想单独指定，就在旁边放一个同名 `.txt`，第一行写核心表达：

```
输入\2026-09-15\晨跑怎么坚持.mp4
输入\2026-09-15\晨跑怎么坚持.txt   ← 第一行写：晨跑怎么坚持
```

> 核心表达的要求：含中文、不超过 36 字、不能只是 `ABC123` 这种编号。

### 第二步 · 跑

回 WorkBuddy 对话里说一句「跑一下输入」，AI 会按 `说明书\AGENT运行守则.md` 的方式代跑 `python 工具\剪辑.py`。

> **别自己双击 `工具\剪辑.cmd`**：cmd 一跑就是黑盒，出错没人接、六个闸口没人裁决。
> 就算在命令行跑，判断 JSON 也该由 AI 来写。

它会自动做完所有机械活：

```
转写 → 建词轴 → 声学对齐 → 字缝吸附 → 表达审查候选 → 建段
     → 结构重排 → 切口清单 → 帧级验收 → 冻结 → 字幕投影 → 生成草稿 → 登记草稿箱
```

### 第三步 · 它会停下来问你（重要，不是报错）

有 **6 件事**属于"编辑判断"，脚本不能替你做 —— 替你做了就是伪造。
跑到那里它会**停住**，并打印：要写哪个文件、有哪些字段、样例在哪。

| 停在哪 | 要写哪个文件 | 一句话说清 |
|---|---|---|
| 内容计划 | `工作区\<片名>\content_plan.json` | 讲给谁、要证明什么、哪些主题块留哪些删 |
| 原声留删 | `keep.json` | 逐个词决定留/删、哪些字要改、哪里切段 |
| 表达审查 | `expression_review.json` | 逐条听原音裁决「嗯/啊/这个」和停顿 |
| 结构编排 | `structure.json` | 最终播放顺序、开头用哪一段 |
| 切口听审 | `cut_review.json` | 逐段头尾 + 逐个删接点听一遍，确认没吞字 |
| 字幕分卡 | `cards.json` | 每段字幕断在哪 |

**这一步一般交给 WorkBuddy 里的 AI 做。** 你只要说一句：

> 把 `工作区\晨跑怎么坚持` 推到下一步

它会读 `说明书\工序与闸口.md`，自己写那个 JSON，然后继续跑。

想自己写也行：`说明书\待填模板\` 里每个文件都有一份**示意样例**（虚构内容，只看字段结构），
照着字段填，但别抄内容。

### 第四步 · 出草稿

全部走完后，草稿出现在剪映的草稿目录，并且**已经登记进草稿箱**：

```
D:\JianyingPro Drafts\<日期>_<核心表达>_剪映草稿
```

打开剪映专业版，草稿列表里就能看到。
同时 `输出\<日期>_<核心表达>\` 里会生成 `交付说明.md` 和一个 `打开草稿.cmd`（双击直接跳到草稿文件夹）。

> **同一天丢了多个视频？** 每期推到交付闸口后，跑一次：
> `python 工具\合并草稿.py 2026-09-15`
> 整批合成**一个**剪映草稿 —— 每个视频一条轨道（轨道名=期名），字幕/配图
> 跟着自己的视频走，时间上首尾相接，能直接播放导出。日期文件夹里只有
> 一个视频时不用管这条，照旧单期出稿。

### 第五步 · 在剪映里确认三项

1. 左上角**项目素材可见**
2. 时间线没有「**无访问权限**」
3. 播放器**能出画面**（顺便看一眼字幕字体对不对）

三项都正常 → 跟 AI 说一声，它会把状态记成「已实机确认」。
有不对 → 把现象描述清楚，别去改 JSON 冒充通过。

## 3. 改设置

`配置\设置.json` 就是全部可调项：

```json
{
  "素材类型": "single_speaker",
  "字幕字体": "新青年体",
  "skill_root": "",
  "剪映草稿根": ""
}
```

| 键 | 说明 |
|---|---|
| `素材类型` | `single_speaker`（单人口播）/ `single_subject_interview`（学员好评采访） |
| `字幕字体` | 剪映内置字体名，711 个可选，全表在 Skill 的 `字体\剪映字体表.json` |
| `skill_root` | 留空 = 自动探测（优先已安装的 Skill） |
| `剪映草稿根` | 留空 = 自动定位 |

改字体只影响**新接的单**。已经建好工作区的期，要改就改
`工作区\<片名>\config.json` 里的 `font`，然后重跑冻结 —— 字体属于样式决策，冻结之后才生效。

## 4. 命令速查

```bat
python 工具\剪辑.py                      接单 + 一路推进（最常用）
python 工具\剪辑.py status               看每期走到哪一步
python 工具\剪辑.py inputs               只列输入里的素材，不动手
python 工具\剪辑.py deliver --only 片名   只交付某一期
python 工具\剪辑.py doctor               环境自检
python 工具\剪辑.py --dry                演练：只报告要做什么
python 工具\合并草稿.py 2026-09-15        同一天多期合成一个草稿（多轨分层+接龙）
```

这组命令平时由 AI 代跑（说一句要干嘛就行）。`剪辑.cmd` 只是给人的备用启动器，等于第一条。

**重复跑是安全的。** 每一步都按"产物在不在"判断做没做过，做完的会跳过。
比如删掉 `cards.json` 再跑，只会重做分卡之后的环节，不会重新转写。

## 5. 出问题

| 现象 | 怎么办 |
|---|---|
| 提示找不到 Skill 本体 | 跑 `doctor`；或在 `设置.json` 的 `skill_root` 写明确路径 |
| 提示缺 torch / faster_whisper 等 | 跑 `doctor` 看缺哪个；用 Skill 的 `部署\bootstrap.cmd` 装 |
| 卡在「等你写 xx.json」 | **正常，不是报错**。补齐文件后再跑一次即可 |
| 某一步失败 | 看 `运行记录\<片名>.log` 最后几十行，完整报错在那 |
| 剪映里看不到草稿 | 草稿已登记，重进一下剪映的草稿列表；确认剪映「草稿位置」设置没变 |
| 剪映提示素材「无访问权限」 | 原素材被移动或权限变了。别改 JSON 冒充通过，按提示重新链接 |

## 6. 边界（先知道，省得踩）

- **只在 WorkBuddy 桌面版 + GLM 5.3 Flash / DeepSeek V4.1 Flash（二选一）上验证过。** 契约层（代码 + 42 项测试）
  跟模型无关；但六个决策 JSON 是模型"想"出来的。换模型会让断句、口头语删留、
  开头选择整体漂移，**而测试仍然全绿、不会报警** —— 你只会拿到一条"看着没错但不对味"的片子。
- 本工作台**只出剪映原生草稿**。Final Cut / FCPXML 在 Windows 版被禁用。
- 支持单人口播、学员好评采访；双人 / 多人内容会被识别后停止（不套用单人口播）。
