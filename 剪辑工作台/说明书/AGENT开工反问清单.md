# Agent 开工反问清单（先问再干，防返工）

> 六闸口的 JSON 一旦写错，返工是整条链路级的（重裁决 → 重建段 → 重合并）。
> **开工前把下面的问题一次问清/一次查清，比跑完再返工便宜十倍。**
> 问不出口的（答案能自己查证的），列为「自检」，不许跳过。

---

## 必问（每批开工，AskUserQuestion 一次问完）

1. **配图是什么、怎么上轨？**
   输入文件夹里的 JPG/PNG 是成品图，还是需要抠图的 sprite sheet？
   → 标准版分发包没有 `配图工厂\`：洋红底 sprite sheet 无人可抠，只能接受成品 PNG
   （手工放图走 `工序与闸口.md` 第 18 步，文件名 = 触发词）。用户另有意图（如只要封面）当场确认。

2. **本批范围是哪几期？**
   状态机 status 里会有别的日期的未交付期。合并必须 `--only` 挑期，不带会把没做的卷进合并组卡死。

3. **交付形态**：合并成一组接龙草稿，还是分期单独出稿？

## 自检（跑 run 之前查，不用问人）

4. **素材有没有挪过文件夹？** config.json 三处路径（proxy/original_path/media.path）+ 两处缓存绑定（`_vad16k.meta.json`、`word_track.json` 的 audio_cache.source）指向哪，素材实际在哪。挪过 → 先同步路径与绑定（sha256 核内容），**别重跑 p1a**。

5. **素材帧率先探底**：开工时 ffprobe 各条素材的 r/avg_frame_rate。VFR 丢帧是常态，别等合并器报冲突再放宽容差。

6. **重复句/废 take 清点**：词轴里同句复述、断头起头逐个标出来。**近重复音频默认两遍都保留**（删其一 → 对齐窗口炸）。真拿不准哪些算废 take，列给用户勾选。

## 按情况问（涉及内容决策，别替用户拍板）

7. **单句长口播的配图**：一句一图 → 整段一个 rough 句时只能上 1 张图。接受？还是要先拆句（属结构改动）？

8. **删改尺度**：口误修到什么程度、口语词删多狠、停顿保多少——首批做完给用户看一份裁决摘要再批量复制到其余期。
