# 工序与闸口 · 给 AI 的操作手册

`剪辑工作台\工具\剪辑.py` 是这套东西的**操作面**。它给口播出稿的管线包了一层：
**机械步骤自动跑完，六个判断步骤停下来等人。**

你的活儿就是：每次它停住 → 读它打印的提示 + 本文对应小节 → 把那个 JSON 写出来
→ 再跑一次。如此循环，直到出草稿。

> **宪法永远是 Skill 的 `SKILL.md`。** 本文只做一件事：把 SKILL.md 的工序映射成
> 「工作台停在哪一步、停下时你必须产出什么、判定标准是什么」。
> 有冲突时，以 `SKILL.md` 和管线脚本的报错为准。

## 0. 位置关系

| 角色 | 位置 |
|---|---|
| 工作台（操作面） | `剪辑工作台\`（本文件所在目录的上一层；与本 Skill 的 `SKILL.md` 同级） |
| Skill 本体（引擎） | 分发包里是项目级 `<工作区>\.workbuddy\skills\kbcg-xgz-win-workbuddy`；装到本机则是 `%USERPROFILE%\.workbuddy\skills\...`（自动探测；可用 `配置\设置.json` 的 `skill_root` 指定） |
| 工作区 | `剪辑工作台\工作区\<片名>\` —— 一期一目录，所有中间产物与决策都在这里 |
| 运行日志 | `剪辑工作台\运行记录\<片名>.log`（完整输出，排错看这个） |
| 交付台账 | `剪辑工作台\输出\全部交付.md`（一行一期，键 = 日期 + 期名） |
| 逐期交付说明 | `剪辑工作台\输出\<日期>_<核心表达>\交付说明.md`（期名 ≠ 核心表达时目录带 `（期名）` 后缀，避免两期互相覆盖） |

入口命令（在 `剪辑工作台\工具\` 下）：

```bat
python 剪辑.py                         接单 + 一路推进
python 剪辑.py status                  进度总览
python 剪辑.py deliver --only 片名      只交付某一期

python 剪辑.py doctor                  环境自检
```

`闸口` 列标 **是** 的必须由你产出文件；标「否」的 `剪辑.py` 会自己跑。

| 9 | **表达审查逐项裁决** | **是** | `p1c_生成表达审查.py <工作区> --check` 退出码 0 | **你** |
| 10 | 建段 | 否 | `segments.json` 存在 | 自动 |
| 11 | **结构编排** | **是** | `structure.json` 存在 | **你** |

| 13 | 生成切口清单 | 否 | `cut_review.json` 存在 | 自动 |

| 15 | F1 验收并冻结 | 否 | `decision_lock.json` 存在 | 自动 |
| 16 | **字幕分卡** | **是** | `cards.json` 存在 | **你** |
| 17 | 字幕时间线投影 | 否 | `captions_plan.json` 存在且比 `cards.json` 新 | 自动 |
| 18 | 配图工厂同步（可选） | 否 | 期 `config.json` 没写 `icon_batch` 自动跳过；写了则 `配图\` 比批次上游新 | 自动 |
| 19 | 配图对齐（可选） | 否 | 没放配图自动跳过；放了则 `配图计划.json` 比图片新 | 自动 |
| 20 | 交付剪映（生成 + 终检 + 登记） | 否 | 见下方「交付阶段的完成判定」 | 自动 |

**第 18 步（配图工厂）怎么用**：口播文稿 → 图标提示词 → AI 生图 → 抠图 →
按文案命名的触发词图标，全流程见 `配图工厂\说明书.md`（其他 agent 只调
`配图工厂\工具\图标工厂.py`，不需要安装抠图 skill）。启用方式：在期的
`config.json` 里加 `"icon_batch": "<批次目录路径>"`，批次更新后期内 `配图\`
自动重同步。接着走第 19 步对齐上时间线。
（**标准版分发包不含 `配图工厂\` 目录**，此步等价于永远跳过；手工放图走第 19 步即可。）

**第 19 步（配图对齐）怎么用**：把图片放进工作区的 `配图\` 文件夹，
**文件名 = 触发词** —— `热身.png` 在讲到含「热身」的第一句时从**句首**出现；
`拉伸#2.png` 是第 2 次出现「拉伸」的那句；`热身_2.5s.png` 显示 2.5 秒
（默认秒数在 `config.json` 的 `image_duration_s`，缺省 4 秒）。
产出的 `配图计划.json` 会列出每张图命中的**整句话**，出草稿前扫一眼核对。
图会以画中画轨（「配图」轨）写进剪映草稿，位置/缩放可在剪映里再调。

**幂等**：判定全部基于产物文件，重复运行安全；只有删掉对应产物才会重跑那一步。

**第 7 步（字缝吸附）为什么不能跳**：强制对齐器给的是「这个字大致落在哪一段」，
不是「声学字缝在哪个采样点」。停顿处两者一致；**连读处会偏 55–190ms**。
实测（2026-09-14 人耳抽听）：`第三步` 的「三」被标成 `24.880-25.200`，
而 24.880 处仍在发声 → 刀口切在「第」字内部，从那段里听到的是「第三」两个字；
「第」只分到 80ms（常速单字 150–250ms）。全片 112 条字缝，**33 条偏 55–190ms**，
人耳可察觉门槛约 70–80ms。第 7 步不做，这些偏差会原样进成片。

它纯后处理、**不重跑对齐模型**，把每道字缝挪到能量谷中心，再按第 6 步同一套规则
重推词级时间。**顺序不能错**：必须在第 6 步之后、第 8 步之前 ——
`expression_review.json` 绑定了 `word_track` 哈希，`segments.json` 会整份抄走
`char_times`。每处位移都记在 `char_snap_report.json`（起止、毫秒、谷深），可复核；
吸附前的词轴存档为 `word_track.吸附前备份.json`，要回退直接换回来。

**交付阶段（第 20 步）的完成判定**（三件事同时成立，缺一就重跑）：

1. `jianying_structural_verification.json` 存在；
2. 它里面 `draft_path` 指的草稿目录**真实存在**（含 `draft_info.json`）；
3. 该草稿**已登记进剪映草稿箱索引**（`root_meta_info.json` 里有一行同名、且
   `draft_fold_path` 指向的目录真实存在）。

只看第 1 条会骗人：报告可能成了「过期件」（它指的草稿已被归档/删除），
或者草稿文件还在但从未登记 —— 后者用户在剪映草稿列表里根本看不到。
索引行与草稿目录都是持久事实，即使用户打开过剪映（剪映会把
`draft_meta_info.json` 改写成加密串）也依然成立。

⚠ **不要删 `word_track.whisper备份.json`** —— 它是「对齐已完成」的标记，
删了会重跑声学对齐，两次对齐叠加会出问题。

⚠ 第 5 步 `validate-keep` **每次都会重新执行**（它是纯校验，没有产物文件）。

## 2. 六个闸口

### 闸口 1 · `content_plan.json` —— 内容计划

先把素材通看一遍，再写这个文件。**JSON 只记录已经做完的判断，不能代替判断。**

先读：`references/material-routing.md`（素材路由）→
`子技能/粗剪/单人口播.md`（或 `学员好评.md`）→ `references/rough-cut-policy.md`

| 字段 | 要求 |
|---|---|
| `goal` | 这条片子要达成什么 |
| `audience` | 受众，具体到人群与处境 |
| `main_claim` | 全片要证明的那一句主张 |
| `topic_blocks` | **必须覆盖全词轴**，不得留空档；每块给 `block_id / start_word / end_word / decision(selected\|exclude) / role / reason` |
| `selected_story` | 选中主线，逐块说明功能与不可替代性 |
| `hook_candidates` | `candidate_id / block_ids / hook_type / strength_reason / open_loop_reason`（引用的是 `topic_blocks` 的 `block_id`，不是段 id——契约按 `block_ids` 校验） |
| `selected_hook` | 选中的候选 id |
| `review` | 见下 |

硬约束：

- 主题块内仍要**按句级信息增量**过一遍：每个保留单元必须新增
  信息 / 证据 / 情绪 / 信任 / 必要承接中的至少一项。
  弱复述、感叹、重新报幕应删除。
- 但设问、步骤起句、改变命题的自我修正**必须先做「删后依赖」检查**，
  不能只因词面重复就删。
- `hook_type` 允许 `natural_premise`（自然前提）——
  **不要因为字段名叫 Hook 就硬造爆点**。
- `review` 必须含**样本证据** `sample_pairs`：从 Skill 的
  `样本库/成对样本清单.json` 选 2–3 组哈希有效的「AI 初稿—用户终版」，
  只学用户实际改动。AI 生成的产物不是用户真值；同一源素材拆出的多条
  只算一个证据家族。

```json
"review": {
  "reviewer_type": "agent",
  "status": "reviewed",
  "reviewed_by": "<你的标识>",
  "reviewed_at": "<ISO 时间>",
  "sample_pairs": [
    {"name": "...", "material_type": "single_speaker",
     "ai_sha256": "...", "final_sha256": "...", "evidence": "diff_only"}
  ]
}
```

样例：`说明书\待填模板\content_plan.样例.json`

### 闸口 2 · `keep.json` —— 原声留删

先读：`子技能/粗剪/单人口播.md` + `references/rough-cut-policy.md`

| 字段 | 含义 | 格式 |
|---|---|---|
| `drop` | 删掉声音 | `[start_word, end_word, 理由]` |
| `fix` | **只修 ASR 文本**，一个字不多一个字不少（等长替换，不动时间） | `[start_word, end_word, "正确文本", 理由]` |
| `retain` | 有意保留的口头语 / 犹豫 / 强调 / 自我修正 | `[word_index, word_index, 功能, 理由]` |
| `split_after` | 两侧声音都留，但建立结构边界 | `[word_index, ...]` |
| `review` | 裁决记录 | 见下 |

硬约束：

- 刀口**只用于真实删减、停顿压缩、重排或明确 `split_after`**。
  **不得为了凑段长参考值额外加刀。**
- **不按词表机械删**「呃、嗯、呢、啊、这个、就是」。要判断删后是否更完整自然，
  以及它是否承担思考 / 强调 / 语气 / 情绪 / 命题修正 / 承接功能。
- 自我修正若改变最终命题，**必须保留最终修正链**，不能按废话删。
- 理由里如果写了引号文本（例：`口头禅：'怎么讲呢'`），p1 会做**下标自校验**，
  对不上就中止 —— 引号里必须是该下标位置的真实词。
- 辅助工具：`脚本\查词.py`（查下标）、`脚本\核专名.py`（查英文缩写与专名）。

```json
"review": {
  "reviewer_type": "agent",
  "status": "reviewed",
  "reviewed_by": "<你的标识>",
  "reviewed_at": "<ISO 时间>",
  "scope": ["content_plan", "keep", "structure", "cut_review"]
}
```

写完后 `剪辑.py` 会自动跑 `validate-keep`，报错就一直改到过。

样例：`说明书\待填模板\keep.样例.json`

### 闸口 3 · `expression_review.json` —— 逐项表达审查

这个文件由 `p1c_生成表达审查.py` **生成候选骨架**，你只填裁决字段。
**不要改 `word_track_sha256` / `keep_sha256`** —— 它们绑定上下文，
改了就等于作废；上游一变（词轴或 keep）必须重建并重审。

先读：`子技能/粗剪/单人口播.md` 的表达审查一节

| 候选数组 | `decision` 取值 | 说明 |
|---|---|---|
| `micro_candidates` | `drop` \| `retain` \| `not_micro` | 口语微成分。`not_micro` = 其实是实义内容 |
| `residual_candidates` | `filler_drop` \| `breath_noise` \| `restore_text` | VAD 检出的词轴外残声 |
| `pause_candidates` | `compress` \| `retain` | 相邻保留词之间的停顿 |

每条都要填：`decision` / `function` / `caption_action` / `reason` / `acoustic_review: "heard"`

硬约束：

- **必须逐项听原音**，`acoustic_review` 才敢写 `heard`。
- `pause_candidates` 是**候选**，绝不自动下刀：
  只有 `ineffective_wait + compress` 才压缩；
  思考、强调、情绪、转折、动作、呼吸、句间气口一律 `retain`。
  **不存在「超过某个秒数一律删」的规则。**
- `not_micro` 意味着它是实义内容（例：「我说的**不是**你」
  里的「不是」是实义否定，不是自我更正标记）。

自检（`剪辑.py` 会自动跑）：

```bat
"%PY%" "<Skill>\脚本\p1c_生成表达审查.py" <工作区> --check
```

样例：`说明书\待填模板\expression_review.样例.json`

### 闸口 4 · `structure.json` —— 结构编排

先读：`知识库/决策模板/结构编排.md`

| 字段 | 要求 |
|---|---|
| `goal` / `audience` / `main_claim` | ⚠ **必须与 `content_plan.json` 逐字一致** |
| `hook_candidates` | `candidate_id / block_ids / hook_type / strength_reason / open_loop_reason`（引用的是 `topic_blocks` 的 `block_id`，不是段 id——契约按 `block_ids` 校验） |
| `selected_hook` | ⚠ **必须与 `content_plan.json.selected_hook` 一致** |
| `intentional_repeats` | 有意重复登记（没有就 `[]`） |
| `sequence` | 按**最终播放顺序**列出全部段：`segment_id / role / reason` |

⚠ **两套 ID，别混**：

- `structure.json` 的 `segment_id` 是**数字**，对应 `segments.json` 里每段的 `id`（0、1、2…）。
- `cards.json` / `cut_review.json` 的 key 是 **`L01.0` 形式的播放键**，来自 `rough_segments.json`。

硬约束：

- 开头**不强制**爆点前置。要前置就必须命中核心、脱离原位仍真实、正文能兑现。
- 开头原声是否在正文复现，唯一判断是：两次功能是否不同，
  删掉正文版本是否损害观众判断或理解。
- 其他倒序必须登记真实性边界和编辑作用。

样例：`说明书\待填模板\structure.样例.json`

### 闸口 5 · `cut_review.json` —— 逐段、逐切口听审

这个文件由 `p2b_生成切口清单.py` 生成骨架（`review.status = "pending"`），
你填完整。**脚本只生成模板，绝不代替听审。**

要求：

1. **逐段**播放词头/气口与韵尾/衰减，核对 `head_preroll_frames` / `tail_release_frames`：
   - 段头默认目标 **≥ 2 帧**预卷，段尾默认目标 **≥ 11 帧**释放
   - 低于目标时**必须**在 `head_margin_exception` / `tail_margin_exception`
     写清安全上界（前方被删声音 / 紧邻发音 / 素材边界）
   - 填 `head_complete` / `tail_complete` 为 `true`，并写**真实**的 `head_note` / `tail_note`
2. **逐个真实切口**连续播放左右两段，确认没有吸住、弹断、吞字、跳气口、
   删词残留或语义突变：
   - `no_deleted_audio` / `semantic_natural` / `joined_playback_checked` = `true`
   - `joined_note` 写**真实备注**，不能批量假填
3. 最后把 `review` 从 `pending` 改成已审：

```json
"review": {
  "status": "reviewed",
  "reviewer_type": "agent",
  "reviewed_by": "<你的标识>",
  "reviewed_at": "<ISO 时间>"
}
```

> **不改 `review.status` 就等于没审** —— 工作台的闸口判定看的就是它。
>
> ⚠ `status` 只能写 `reviewed` 或 `approved`（契约 `_validate_basic_review`）。
> `agent_reviewed / human_reviewed / human_approved` 属于**另一个字段**：它由契约脚本
> 按 `reviewer_type + status` **算出来**写进 `decision_lock.json` 的 `review.level`，
> 不是给人填的。把这套值写进 `status` 会被判成「尚未裁决」，F1 直接不冻结。
> agent 不得写 `approved` —— 契约显式拒绝伪造人工批准。

样例：`说明书\待填模板\cut_review.样例.json`

### 闸口 6 · `cards.json` —— 字幕分卡

**注意分工**：这个文件只决定「**字幕断在哪**」。声学对齐（P3）和样式（P4）
是后面自动跑的，不要在这里插手。

先读：`知识库/决策模板/字幕分卡.md`

结构：

```json
{
  "L01.0": [ ["三次晨跑三次放弃"], ["不是我不行", "不行"] ],
  "L01.1": [ ["是方法不对", "方法"] ]
}
```

- key = `rough_segments.json` 的播放键，**必须完全一致**（不能多也不能少一个段）
- 每张卡 = `[文本, 关键词]`，`文本` 必须**逐字守恒**（片段内所有字都要出现，
  且顺序一致，不增不减）
- 关键词必须是该卡文本的**子串**；它只是 P5 上色**候选**，P2 一律不上色

硬约束：

- **不得在多字词或英文 token 内部切卡**：`账号`、`视频号`、`方法论`、
  `ALL IN`、`INTJ` 这类必须作为原子单位。语义上觉得更匀也无权覆盖这条边界。
- 竖版每张卡 **≤ 10 个全角字宽**（横版 13）。
  过长时在**新谓语、宾语、转折、状语收束或新意群之前**换成下一张卡，
  **不在卡内硬换行**，也**不按字数机械均分**。
- 不隐藏仍在播放的声音；每个字都要归属真实发音片段。

**写完卡必须跑断点自检**（2026-09-29 医生口播实测新增；机械贪心分卡曾把
「白带」切成「…是好白|带呢」——字宽合规、契约全绿，术语还是被切坏了）：

```bat
"%PY%" "%BASE%\脚本\核断点.py" <工作目录>
```

三类候选：① 术语切界（医疗词被切在卡界，最伤口播信任）②「的/是」悬尾
（意群没收干净）③ 单字孤卡。只列候选不判对错；逐条按意群重切到干净再进
第 17 步。句末语气词（了/呢/啊）收尾是正常句界，不算问题。
注意：ASR 词轴按字切分，「白带」「厘米」这种术语在词轴里是两个独立字，
现有 caption_boundary_contract 的不可拆单元**管不到它们**——这就是
必须跑本脚本的原因。

样例：`说明书\待填模板\cards.样例.json`

## 3. 交付与实机验收

交付步（`finalize jianying`，状态机最后一步）内部依次做：

```
验证决策锁 → p3 分卡投影 → p1b 帧级验收 → 准备交付素材
          → 生成剪映草稿 → 草稿终检 → 登记草稿箱
```

> **合并组例外（2026-09-15）**：期的 config.json 带 `合并组`（同一日期文件夹
> 丢了 ≥2 个视频时由 intake 自动打标）则不在本阶段单独出稿 —— 状态停在
> 「等合并」，跑 `工具\合并草稿.py <日期>` 把整批合成一个剪映草稿
> （每期一条视频轨+自己的字幕/配图轨，首尾相接）。合并完成后期工作区
> 会有 `合并交付.json`，本阶段视为完成。

跑完得到的只是 `complete_structural` —— 它证明**工程结构正确**，
**不证明剪映界面里能看到素材**。

必须接着让用户在自己登录的剪映里确认三项（剪映是桌面 Qt 应用，
WorkBuddy 够不到它，只能人工）：

1. 左上角项目素材可见
2. 时间线没有「无访问权限」
3. 播放器能出画面

用户确认后，跑：

```bat
"%PY%" "<Skill>\脚本\p4j_记录剪映实机验收.py" <工作区> ^
  --material-bin-visible yes --timeline-media-accessible yes ^
  --preview-frame-visible yes --evidence-note "<用户如何检查的>"
```

三项全 yes 才会写 `complete_runtime_verified`，DoD 才算闭合。

**记完之后要再跑一次 `剪辑.py`** —— 交付说明和总台账是「跑的时候生成」的，
`p4j_记录剪映实机验收.py` 只写工作区里的 `jianying_runtime_verification.json`。
不重跑的话台账里那行还停在 `complete_structural`。重跑是幂等的，不会再出草稿。

出现「链接媒体」「无访问权限」时：先读 `media_delivery.json.sources[].delivery_path`，
用剪映自己的「重新链接 / 导入」界面选那个路径。
**不得伪造授权标记或只改 JSON 冒充通过。**

## 4. 返工：问题只回到所属工序

用户反馈先归类，再改。硬边界（详见 `references/stage-boundaries.md`）：

| 问题 | 只回这一工序 |
|---|---|
| 选材、顺序、重复、口头语、刀口、尾音 | P1（改 `keep` 等）→ 必须重新冻结 |
| 错字、漏字、断句、关键词候选 | P2（只改 `cards.json`） |
| 字幕早出/晚出、段首空帧、换卡不贴发音 | P3（自动，不用手改） |
| 字体、字号、颜色、X/Y 位置 | P4（改 `config.json` 的 `font`，重跑冻结） |
| 音乐、音效、概念大字、调整层、转场 | P5 |
| 文件格式、素材路径、工程结构 | P6 |

改之前先开隔离锁，改完必须验证；上游任一不变量漂移即失败：

```bat
"%PY%" "<Skill>\脚本\stage_scope_guard.py" begin <工作区> <scope> [--force]
rem 只改当前 scope，再按既定顺序重生成下游产物
"%PY%" "<Skill>\脚本\stage_scope_guard.py" verify <工作区>
```

⚠ **改了被冻结的决策，决策锁会失效**，必须重跑冻结：

```bat
"%PY%" "<Skill>\脚本_win\pipeline.py" f1 <工作区> --force
```

（`f1` 报「决策锁已存在」不是 bug —— 契约禁止静默覆盖，所以必须显式 `--force`。）

## 5. 汇报口径

交付报告必须分开说四件事（见 `SKILL.md` 的「交付报告」）：

1. **内容方法** —— 核心表达、受众、选材、开头、排序、删除理由
2. **粗剪执行** —— 时长、留删/修正/有意保留、真实切口、听审、锁状态
3. **包装验证** —— 仅当真的进了阶段二才报
4. **证据边界** —— 「技术通过」「Agent 内部验收」「用户事后精调反馈」**必须分开表述**

`complete_structural` 只能说「工程结构已生成」，**不能说「剪映交付完成」**。
用户只给了一句整体认可时，不要把它拆成「每个刀口、每张字幕卡、每项包装均被逐项确认」。

没有经过新素材前向测试时，**不承诺**「完全一致 / 百分百学会 / 绝不返工」。
