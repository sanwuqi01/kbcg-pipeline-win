# 单人口播成片包装

这是 `single_speaker` 在 F1 内部验收并冻结后的完整包装入口。它不重新决定讲什么，只把已经成立的论证变得更容易理解、记住和观看。用户只要求字幕时不要读取或执行本文件。

## 一、先锁权限和口播核心

开始前确认三件事：

1. F1 粗剪锁有效，或用户提供了明确冻结的人工粗剪 XML；
2. 用户授权的是完整包装还是指定组件；
3. 输入 XML、原素材和当前口播音频覆盖均已记录路径与 SHA-256。

包装可以新增连接式标题、音乐、音效、调整层、局部画面处理和转场。它不能改变冻结对白的文字、来源、范围、顺序和连续性。若内容需要改动，退回粗剪；若只为缩放、定格或局部效果拆开视频和音频，必须让原对白继续完整播放。

基础字幕不是一个可随包装反复改动的整体。它必须依次经过：P2 文字与断句确认 → P3 声学对齐确认 → P4 画幅样式确认。进入其他包装后，三层都成为只读输入；字幕哪一层出错，只回对应层修正。

## 二、先画语义章节，不按秒数铺效果

通看片子，把当前内容按实际功能标成：前提、例子、浅层解释、深层机制、设问、方法、结论和自然收束。随后只在以下位置考虑包装节点：

- 新章节开始，观众需要知道接下来在讲什么；
- 抽象概念第一次成立，需要一个清晰记忆点；
- 真实案例或声音证据出现，需要帮助观众建立联想；
- 设问、反转、自我吐槽或包袱落地，需要节奏变化；
- 方法或结论收束，需要从情绪回到可执行信息。

长时间没有效果不等于包装不足；连续高密度效果也不等于节奏好。判断标准是它是否帮助当前论证，而不是“隔几秒必须刺激一次”。

## 三、文字分成四种职责

1. **开场命题**：用极少文字建立问题和观看理由；它是标题，不是逐字稿。
2. **基础字幕**：唯一的口播真值层。逐字对应保留声音，按句法断句并用字符级时码对齐。
3. **概念强调**：把已经说出的核心词放大或改变位置，帮助形成记忆点；不能每句话都做。
4. **编辑批注**：对自我修正、反差、口头禅或包袱做人格化提示，例如对一次比喻失误作轻量吐槽。它可以增强人物感，但不能冒充说话人原话。

四层必须在工程结构和验收中分开。基础字幕仍遵守画幅 profile；不能因为某个概念大字用了更大字号，就把全部字幕一起放大。

已确认的竖屏基础 profile 按精确画幅分开执行：1080×1920 使用聚珍体、字号 50、居中、X=0、Y=-220；2160×3840 使用聚珍体、字号 52、居中、X=0、Y=-190，并使用黑色 75% 投影、0.63 模糊、距离 2、角度 315°。段首首字距离切口不超过 2 帧时，首卡贴切口；段内换卡仍按下一卡首字的真实起音。前者属于 P3 对齐，后面的字体/位置/投影属于 P4 样式，不能混为“字幕整体调整”。

## 四、画面分成全局基线和局部强调

**全局基线**负责整片统一：曝光、色彩、对比和整体质感。尽量用贯穿全片的调整层或等价非破坏结构，不要把同一组参数复制到每个口播片段。

**局部强调**只服务具体语义：短时缩放、透明度、定格、局部调整层、章节转场或画面节奏变化。每一个局部效果都要能回答“它强调的是哪句话、哪次反转或哪个证据”。

若局部画面处理会影响对白，先把音视频解耦：画面可以拆、缩放或定格，冻结对白不能因此被截断、重复或错位。粗剪主线与包装画面结构可以不同，但口播音频覆盖必须一致。

## 五、声音先保证对白，再做氛围

顺序不可倒置：

```text
对白响度与清晰度
→ 章节音乐
→ 论证型声音证据
→ 节点音效
→ EQ、音量、淡入淡出和交界复核
```

- **对白**永远是主信息。先统一可懂度，再决定其他声音能放多大。
- **章节音乐**承担情绪和认知阶段变化，不按固定时长平均铺。音乐切换应对应章节变化。
- **论证型声音证据**不是装饰。例如说话人讲“新闻联播的声音”“天气预报的声音”时，实际声音能直接证明“声音会触发记忆”这一观点。
- **节点音效**服务转场、反转、概念落点或人格包袱。没有明确编辑作用就不加。
- 每次声音进入和退出都检查对白遮蔽、突兀跳变和尾音；必要时使用音量、EQ 与淡入淡出，而不是只把素材扔到时间线上。

## 六、保留说话人的人格节奏

单人口播不是只有信息密度。自我修正、冷笑、反问、口头禅和比喻翻车可能构成人物辨识度。粗剪先判断声音是否值得保留；包装再决定是否用短批注、并列文字或轻音效把它变成节奏点。

这类处理必须克制：它的作用是让观众更认识这个人、缓解长论证的密度，不能持续抢夺主信息。

## 七、工程执行顺序

1. 复核粗剪锁、输入哈希、原始画幅、帧率、旋转和音频属性；
2. 完成基础字幕的修字、句法分卡和声学对齐；
3. 建语义章节图，标出少量包装节点；
4. 先做开场命题和文字层级，再做全局画面基线；
5. 在明确节点添加局部画面强调，需要时解耦音视频；
6. 先处理对白，再加入章节音乐、声音证据和节点音效；
7. 复核混音、画面、字幕和口播连续性；
8. 按 Final Cut 或剪映的真实结构序列化并验收。

当前 `p4f/p4j` 的脚本化稳定边界是基础字幕与平台工程。完整包装中无法由现有脚本安全表达的专有插件、调色或复杂效果，不得声称已自动复现；应保留用户已有节点，或明确交付仍需人工补齐的组件。

## 八、交付自检

- 项目画幅、帧率、旋转和素材引用是否保持原值？
- 冻结对白的来源、范围、顺序和连续性是否保持？
- 基础字幕是否仍等于真实保留声音，编辑批注是否与之分层？
- 包装节点是否都对应章节、证据、反转、方法或结论，而不是平均撒点？
- 全局调整和局部强调是否分开？局部处理是否误伤对白？
- 对白是否始终清楚，音乐和音效的进出是否自然？
- 声音证据是否真的帮助论证，而不是只做热闹？
- XML/草稿结构和对应平台验收是否通过？
