### 为什么模型要钉在推荐档

这个 Skill 分两层：

- **代码层**（`脚本/`、`脚本_win/`，共 53 个文件）—— 转写、对齐、建段、帧级验收、生成草稿。这一层是**确定的**，换谁来跑都一样，`tests.test_learning_contracts` 42 项会盯住它。
- **决策层**（`content_plan.json`、`keep.json`、`expression_review.json`、`structure.json`、`cards.json`、`cut_review.json`）—— **这一层是模型"想"出来的，不是算出来的**。

决策层决定：哪句留哪句删、口头语算不算废字、开头选哪句、字幕怎么断。

换推荐清单之外的模型，这些判断会整体漂移——**而 42 项契约测试仍然全绿**，因为契约只管格式、哈希和内部一致性，管不了"这个判断对不对"。测试不会报警，你只会拿到一条"看起来没错但就是不对味"的片子。

**为什么是这两个**：GLM 5.3 Flash 和 DeepSeek V4.1 Flash 都经过实测验证——性价比高、速度可接受，判断质量在同一档。清单外的模型不是不能跑，是没人替你验过判断质量。

所以：**宿主 + 模型必须落在推荐档内。** 这条已经写进 `SKILL.md` 的「宿主与模型约束」节：开工前若发现宿主或模型不符，Skill 必须停下来向你报告，不得静默开工。

## §3 三步装好

### 3.1 装 WorkBuddy，选对模型

1. 装 WorkBuddy 桌面版。
2. 新建会话时，**模型选 `GLM 5.3 Flash` 或 `DeepSeek V4.1 Flash`**（实测推荐档：性价比高、速度可接受）。选了清单外的模型就换会话，不要凑合。

### 3.2 解压，打开工作区

解压 zip，里面只有一个顶层文件夹（`口播视频剪映出草稿-xgz-win-workbuddy-完整版` 或 `口播视频剪映出草稿-xgz-win-workbuddy-标准版`）。
**这个文件夹本身就是一个 WorkBuddy 工作区**：Skill 放在 `.workbuddy\skills\` 里（项目级技能位），
工作台在根下。不用往用户目录拷任何东西。

在 WorkBuddy 里「打开文件夹」，选这个顶层文件夹，Skill 就被识别了。

> 想全局可用（任何工作区都能触发）的话，也可以把 `.workbuddy\skills\kbcg-xgz-win-workbuddy`
> 整个文件夹拷到 `%USERPROFILE%\.workbuddy\skills\` —— 两种装法二选一，内容完全一样。
> ⚠ 文件夹名必须是 `kbcg-xgz-win-workbuddy`，改名会识别不到。

下文凡写 `<工作区>` 的地方，都指这个顶层文件夹；`<skill>` 指
`<工作区>\.workbuddy\skills\kbcg-xgz-win-workbuddy`。

### 3.3 跑一键适配

打开 **命令提示符**（不是 PowerShell 也行），执行：

```cmd
cd /d "<工作区>\.workbuddy\skills\kbcg-xgz-win-workbuddy\部署"

```


### 3.4 装好之后：怎么开工（入口只有一个——对话里叫 AI）

这个 Skill 有两种用法，**跑的是同一套 `脚本\` / `脚本_win\`、同一套契约、同一个工作区**，
不是两个版本，也不是二选一：

| 入口 | 适合什么情况 | 怎么起 |
|---|---|---|
| **剪辑工作台** | 想让机械步骤全自动，判断闸口仍由 AI 把关 | 视频丢进 `剪辑工作台\输入\`，然后在对话里说「用口播出稿，跑一下输入」，由 AI 引导推进（**别双击 剪辑.cmd**——没有 AI 在场，没人审错误、没人盯闸口） |
| **对话式** | 想边聊边定，或中途要改某个判断 | 在 WorkBuddy 里说「用口播出稿，把这条剪一下」 |

工作台是「机械步骤全自动 + 六个编辑判断停下等人」。它停住**不是报错** —— 是在等你去
`剪辑工作台\工作区\<片名>\` 写那个决策 JSON。要写什么、字段怎么填，
`剪辑工作台\说明书\工序与闸口.md` 逐条写了，六个真实样例在 `剪辑工作台\说明书\待填模板\`。

两条路**可以来回切**：工作台停在闸口时，你手写 JSON 让它继续也行；对话式跑到一半，
也能用下面这条看工作台的状态：

```cmd
cd /d "<工作区>\剪辑工作台\工具"
"<工作区>\.workbuddy\skills\kbcg-xgz-win-workbuddy\.venv\Scripts\python.exe" 剪辑.py status
```

三件进阶的事，各有一份说明书：

- **给片子加小图标配图** → 走 `剪辑工作台\配图工厂\`（**仅完整版含此目录**；
  `配图工厂\说明书.md` 从头讲：文稿 → 图标提示词 → AI 生图 → 抠图 → 触发词.png）。
  先记一条铁律：**洋红底的 sprite sheet 不许直接丢进期的 `配图\` 目录**——
  必须走配图工厂抠成透明 PNG 再 sync 进去，否则洋红背景会整张进片。
  标准版用户可以手工把「触发词.png」放进期的 `配图\` 目录，p4i 配图对齐照样生效。
- **同一天多期合成一个草稿** → 用 `工具\合并草稿.py <日期>`（可加 `--only "期甲,期乙"`），
  不要单期逐个出稿。
- **宿主 AI 的开工须知** → `说明书\AGENT开工反问清单.md`（跑批前 AI 应自查的反问项）
  和 `说明书\AGENT运行守则.md`（宿主环境、闸口裁决脚手架、已修死的坑）。对话式入口
  跑批前 AI 应先读这两份。

> 工作台的 `输入\` `输出\` `工作区\` `运行记录\` 在包里是**空目录**（只有占位说明）——
> 你自己的片子、交付台账、运行日志长在你自己机器上，不会跟别人的混在一起。

## §4 手动装（bootstrap 失败时照这个排）

### 4.1 管线 Python 环境

需要一个装齐 12 个包的 Python。**没有显卡也能跑**，只是转写慢约 3.7 倍（实测 RTF 0.547 CPU vs 0.147 CUDA）。

```cmd
:: 用任意 Python 3.11+ 建环境（这里建在 skill 根下，脚本会优先用它）
cd /d "<skill>"
python -m venv .venv

:: 基础依赖
".venv\Scripts\python.exe" -m pip install -r 部署\requirements-pipeline.txt

:: torch 单独装（要配专用源）
::   有 NVIDIA 显卡：
".venv\Scripts\python.exe" -m pip install torch==2.14.0 torchaudio==2.11.0 --index-url https://download.pytorch.org/whl/cu126
::   无显卡，把上面那行的 cu126 换成 cpu

:: 自检
.venv\Scripts\python.exe 脚本_win\pipeline.py doctor
```

> **为什么 torch 要单独装**：CUDA 轮子 2.42 GB，只在 PyTorch 自己的源上有。国内直连约 2015 KB/s，约 21 分钟。
> **判断 pip 是否还在下载，看 `%TEMP%\pip-unpack-*\` 下的临时文件尺寸，不要看 `pip cache` 体积**——pip 是下载完成后才落缓存的，看缓存会误判成卡死。

`doctor` 里那 12 个模块必须**全是 ✓**。少一个就跑不起来。

### 4.2 ffmpeg / ffprobe

在 PATH 里就行。Windows 常用两种装法：

```cmd
:: scoop（推荐）
scoop install ffmpeg

:: 或到 gyan.dev / BtbN 下 build，把 bin 目录加进 PATH
```

验证：`ffmpeg -version` 能出版本号。

### 4.3 CapCutMate

**必须锁到我们验证过的那一个提交**，换提交会让草稿的版本字段和字体块结构漂移。

```cmd
cd /d "%USERPROFILE%"
mkdir Developer 2>nul & cd Developer
git clone https://github.com/Hommy-master/capcut-mate.git
cd capcut-mate
git checkout 96f36486a9341ae1ad9c81d8f087d2b4caa2eac6

:: ⚠ 关键一步：checkout 会静默留下残缺工作树（少 30+ 个文件）
git status
::   如果看到一堆 " D xxx"，说明工作树残缺：
git checkout -f
git status

:: 建 venv 装依赖
python -m venv .venv
".venv\Scripts\python.exe" -m pip install -r "<skill>\部署\requirements-capcutmate.txt"
```

> 上游仓库自带 `uv.lock`，但你机器上不一定有 `uv`。**用上面这套 venv 等价路径就行**，不用专门去装 uv。
>
> 装到别的盘也可以，装完设一个环境变量告诉脚本：
> ```cmd
> setx CAPCUT_MATE_HOME "D:\Developer\capcut-mate"
> ```
> 设完要**新开一个命令行窗口**才生效。

### 4.4 模型 ×3

| 模型 | 大小 | 怎么来 |
|---|---|---|
| `mobiuslabsgmbh/faster-whisper-large-v3-turbo` | 1546 MB | 用包里的脚本拉（见下） |
| `Qwen/Qwen3-ForcedAligner-0.6B-hf` | 1830 MB | 首次跑对齐时自动拉进 HF 缓存 |
| `silero-vad` | 随包 | pip 装 `silero-vad` 时一起来 |

ASR 模型手动拉（`bootstrap` 做的就是这件事）：

```cmd
cd /d "<skill>"
".venv\Scripts\python.exe" -c "import sys; sys.path.insert(0,'脚本_win'); import 转写_faster_whisper as m; from pathlib import Path; print(m.fetch_model('large-v3-turbo', Path('模型/asr'), False))"
```

网络慢就加镜像：

```cmd
set HF_ENDPOINT=https://hf-mirror.com
```

> ⚠ **镜像 + HF Xet 存储会 401**：某些模型走镜像时 `snapshot_download` 报 `cas-server.xethub.hf.co ... 401`。遇到就**去掉镜像直连重试**，别反复重试镜像。
>
> ⚠ **HF 缓存在 Windows 上会静默损坏**：`blobs/` 里数据完好，但 `snapshots/<rev>/` 下的文件是 **0 字节**空文件，加载时报 `model.bin is incomplete`，看起来像文件坏了。**不要急着重下几百 MB**——删掉那个 0 字节的 snapshots 目录再拉一次就好。

### 4.5 剪映专业版

装上，**并且启动过至少一次**（否则草稿位置没写进设置，脚本找不到草稿箱）。

草稿实体可以在剪映「设置 → 草稿位置」里改到别的盘，脚本会自动探测，不用你告诉它。实测本机是 `D:\JianyingPro Drafts\`。

验证：

```cmd
cd /d "<skill>"
".venv\Scripts\python.exe" 脚本_win\pipeline.py doctor
```

`--- 剪映草稿根 ---` 那一节要打出两个具体路径（草稿实体 + 索引），不能是 ✗。

### 4.6 字体表

**包里已经带了**（`字体/剪映字体表.json`），一般不用动。

要重建或加字体（比如剪映升级后字体表变了），CapCutMate 装好之后：

```cmd
".venv\Scripts\python.exe" 脚本_win\gen_font_table.py
```

字体是**参数**，不是写死的：建工作区时用 `--font` 指定，写进 `config.json.font`，生成草稿和验收读同一份真值。

```cmd
".venv\Scripts\python.exe" 脚本\p0_建工作区.py "D:\素材\我的片子.mp4" --material-type single_speaker --font 新青年体 --core-expression "<中文核心表达>"
```

> 换了字体**必须同时调字号和位置**（各字体的视觉重量不一样），否则字幕会挤在一起或飘到画面外。参见 `SKILL.md` 的 P4 节。
>
> 字体的 `path` 字段是 CapCutMate 写的占位符，剪映**按资源 id 解析字体**——这是上游的刻意行为，不要改。

### 4.7 环境变量（通常不用设）

| 变量 | 什么时候要设 |
|---|---|
| `XGZ_PIPELINE_PY` | 管线环境不在标准位置（不是 `.venv` 也不是受管 `asr-win`） |
| `CAPCUT_MATE_HOME` | CapCutMate 不在 `%USERPROFILE%\Developer\capcut-mate` |
| `HF_ENDPOINT` | 网络慢，走 `https://hf-mirror.com` |
| `HF_HOME` | 想把 HF 缓存放到别的盘（模型默认占 C 盘约 2 GB） |

`setx` 设完**必须新开窗口**。

## §6 故障排查

| 症状 | 原因 | 解法 |
|---|---|---|
| `⛔ 找不到 Windows 管线解释器` | 环境没建、或在非常规位置 | 设 `XGZ_PIPELINE_PY` 指向装了那 12 个包的 python.exe |
| `⛔ 管线解释器缺少依赖 ['jieba']` | `jieba` 是隐式依赖（`p1_建段.py` 才 import 它），容易漏 | `pip install jieba==0.42.1`。**这也是为什么 `doctor` 把它列进探测清单** |
| 控制台崩在半路、错误信息是乱码 | Windows 控制台 GBK + 脚本输出 emoji | 只从 `pipeline.py` 入口跑（它会强制 `PYTHONUTF8=1`）；**不要**直接用系统 `python` 调 `脚本/` 下的文件 |
| `⛔ 缺少 CapCutMate Python 环境` | 没装 / 位置不对 | 见 §4.3；或设 `CAPCUT_MATE_HOME` |
| CapCutMate `git status` 一堆 ` D` | `checkout` 静默留下残缺工作树 | `git checkout -f`，再 `git status` 核对 |
| 模型加载报 `model.bin is incomplete` | HF 快照是 0 字节空文件 | 删掉那个 snapshots 目录重拉；**别急着重下** |
| `snapshot_download` 报 `cas-server.xethub.hf.co 401` | 镜像与 HF Xet 存储不兼容 | 去掉 `HF_ENDPOINT` 直连重试 |
| 下载看起来卡死不动 | 在看 `pip cache` 体积 | 改看 `%TEMP%\pip-unpack-*\` 里的临时文件尺寸 |
| `doctor` 报 `主轨片段N原素材映射错误` | 路径分隔符不一致（Windows 专属坑） | 正常不该出现；生成侧已统一为正斜杠。若出现，报表里带上 `draft_content.json` 的 `materials.videos[*].path` |
| 草稿登记被拒 `同名不同 id` | 索引里留了上一版草稿的悬空行 | **先备份 `root_meta_info.json`**，再按 `draft_id` 精确删掉悬空行；不要去改登记脚本削弱保护 |
| 字幕字体不对 | 字体名没命中字体表，或换了字体没调字号 | 用 `字体/剪映字体表.json` 里存在的字体名；换字体要同步调字号与位置 |

## §7 你改完了怎么再打一个包

改完 Skill 内容，在维护机上跑：

```cmd
cd /d "<win-port>\部署"
python 打包分发.py                    :: 完整版 + 标准版一次产齐
python 打包分发.py --variant full     :: 只打完整版（含配图工厂）
python 打包分发.py --variant lite     :: 只打标准版（无配图工厂）
```

会生成 `分发包\口播视频剪映出草稿-xgz-win-workbuddy-完整版-<日期>.zip` 和 `...\标准版-<日期>.zip`——
**工作区布局**：zip 里只有一个顶层文件夹，内含 `README.md`、
`.workbuddy\skills\kbcg-xgz-win-workbuddy\`（项目级 Skill）和 `剪辑工作台\`。
新用户解压后直接用 WorkBuddy 打开这个文件夹，不用再拷到用户目录。自动排除：

- `模型/`（3.4 GB 实体会让包没法传）
- `__pycache__/`
- `.spike_tmp`、诊断残留、`.工作区` 之类

**会把 `剪辑工作台\` 一并打包进去**（自动定位，也可以用 `--workbench "D:\剪辑工作台"` 指定）。
带上工作台是为了让新用户两条路都能走，所以打的时候对它做了三条过滤：

- `工作区\` `输出\` `运行记录\` —— 只带空壳 + 占位说明，**不带跑过的痕迹**（否则新用户一打开会看到别人的片子）；
- `输入\` 下的素材 —— **一律不带**，素材是用户的东西；
- `输入\` 下的 `.md` / `.txt` 说明 —— 保留，新用户得知道往哪儿放；
- `配图工厂\批次\` —— 只带 `2026-09-15_两种白带` 这个跑通样例（新用户照着学），
  其余生产批次是你的数据，**一律不带**。

标准版额外剔除 `配图工厂\` 整个目录和 `tests\test_icon_factory.py`；
`脚本\p4i_配图对齐.py` 两版都保留（手工放「触发词.png」也能对齐）。

并在 zip 里留下一个空的 `模型/.gitkeep` 占位，保证解压后目录结构完整。

打完后**顺手做个自检**（`打包分发.py` 会自动跑）：必需文件齐全、`SKILL.md` frontmatter 完整、契约回归在打包源上全绿、zip 内容逐项核验（含标准版剔除项为零）。任何一项不过就直接报错，不会产出坏包。

## 附录 B · 这台机器上"不能做"的事

明确的边界，别踩：

1. **不要在 Windows 上生出 FCPXML。** `final-cut` / `both` 分支的代码在仓库里保留作对照，但宿主层**禁用**。用户要 Final Cut 时必须停下来告诉他本版不支持。
2. **不要往真实剪映草稿箱里写测试草稿。** 一律用临时目录。
3. **不要移动或删除用户的素材。**
4. **不要改 JSON schema。** `config.json` / `word_track.json` / `keep.json` / `cards.json` / `captions_plan.json` / `decision_lock.json` 的字段名与语义是 42 项契约测试和所有契约脚本的地基。
5. **不要为了"过测试"去改测试。** 平台差异确实需要改的，先在 `02_实测记录.md` 登记再改。
6. **`material_type` 是冻结项。** 写进 `config.json` 并进 `decision_lock` 哈希；冻结后改动等于锁失效，全链要重跑。
