# 粗剪决策规则

本文件只服务阶段一粗剪：决定内容、原声留删、结构和真实切口。它不写字幕卡、不套字幕样式，也不研究音乐或花字；粗剪冻结后由主 Skill 决定是停下交付原声粗剪，还是进入独立包装阶段。采访学员好评还必须先读对应子技能，先完成“为什么这样选和这样排”的内容决策。

## 粗剪的交付边界

粗剪只回答四件事：

1. 原素材里哪些声音保留、删除或纠错。
2. 每个保留语义单元的准确起止位置。
3. 成片先讲什么、后讲什么。
4. 每一段在结构中承担什么作用。

粗剪不得靠 B-roll（补充画面）、音乐、动画、花字或转场遮盖内容问题。原声音频可以删除、压缩停顿、移动完整语义单元，但不得发明未说过的话，也不得为了顺序好看改写原意。

## 先做内容地图

同类型开工先按 [`sample-evidence.md`](sample-evidence.md) 读取 2–3 份经哈希确认的成对样本，只提取“AI 初稿 → 用户终版”的实际差异。随后通读当前素材，先写 `content_plan.json`，再写 `keep.json`：

下例假设 `word_track.json` 恰好有 120 个词（下标 `0..119`）：

```json
{

  "audience": "正在为公司搭智能体的非技术负责人",
  "main_claim": "先梳理流程和标准，再让 AI 稳定执行",
  "topic_blocks": [
    {
      "block_id": "B01",
      "start_word": 0,
      "end_word": 39,
      "decision": "selected",
      "role": "root_cause",
      "reason": "解释结果不稳定的根因，承担主线起点"
    },
    {
      "block_id": "B02",
      "start_word": 40,
      "end_word": 79,

      "hook_type": "natural_premise",

    }
  ],
  "selected_hook": "H01",
  "selected_story": [
    {"block_id": "B01", "role": "root_cause", "reason": "先解释失败根因"}
  ],
  "review": {
    "status": "reviewed",

        "material_type": "single_speaker",
        "ai_sha256": "7eacdefb0cb49ea75ff1d9a91865d942e9b5b8bdcce66d9453d4d939c7204735",
        "final_sha256": "a6f274edc2206cc52fc1d9b1ffbd75919d1a20bda514bd0dc2c519e876b26b0b",
        "evidence": "diff_only"
      },
      {
        "name": "AI编程要不要懂代码",
        "material_type": "single_speaker",

        "final_sha256": "09a7185c7309c1771ef44428895c10cec1b95181dc2b38d2f0bc6e6110876f49",
        "evidence": "diff_only"
      }
    ]
  }

```

- `topic_blocks` 必须按词下标顺序从 0 开始，以包含端点的 `start_word` / `end_word` 无缝、无重叠覆盖到末词；每块必须有唯一 `block_id`、`decision`、`role` 和 `reason`。
- `decision` 只能是 `selected` / `candidate` / `exclude`。`candidate` 是“可做另一条成片”，不是“暂时也塞进当前成片”；当前工作目录中所有 `candidate` / `exclude` 词都必须完整进入 `keep.drop`。内容地图本身不逐词删口头语。
- `selected_story` 的每项必须写 `block_id` / `role` / `reason`，且必须恰好覆盖全部 `selected` 块，不得引用 `candidate` 或 `exclude` 块。
- `hook_candidates` 是兼容字段，实际表示“开头候选”。它用 `block_ids` 引用内容块，每项必须写 `candidate_id` / `hook_type` / `strength_reason` / `open_loop_reason`，只能引用当前成片的 `selected` 块；`selected_hook` 必须引用其中一个 `candidate_id`。自然完整开场使用 `hook_type=natural_premise`，`open_loop_reason` 写正文怎样继续推进；字段名不能成为强造爆点的理由。
- `review` 必须有 `reviewer_type` / `status` / `reviewed_by` / 带时区的 `reviewed_at`，并登记两到三份与当前 `material_type` 完全相同的成对样本。名称和哈希必须来自 `样本库/成对样本清单.json` 并与磁盘文件复核一致；每对 AI/终版文件摘要必须符合清单格式且不相同，`evidence` 只能是 `diff_only`。
- 若精删后主线或 Hook 已不成立，先更新并重新审阅 `content_plan.json`，不得只改下游文件。

## 再修转写与精删

先区分三类问题：

- 人说错后自我纠正：删除错误半句，保留后一次正确表达。
- 人说对、ASR（自动语音识别）听错：写入 `fix`，时间不变。
- ASR 幻觉或漏词：必须结合音频复核；不能把强制对齐结果本身当存在证明。

不确定是语音还是转写时先标记复核，不得直接按语义猜一个文本后强行贴到音频。

`keep.json` 在内容地图基础上做逐词三态决策：当前主线之外的 `candidate` / `exclude` 块必须全部 `drop`；`selected` 块再精删口头语和冗余。候选块是内容地图里给其他成片保留的索引，不是当前片的待定音频。若复核后改变块级取舍，先同步更新 `decision`、`selected_story`、Hook 和 review，再写下游文件。

当两个相邻词都要保留，却必须在其间建立结构段边界时，在 `keep.json.split_after` 写前一词下标。例如 `"split_after": [57]` 表示在词 57 后断段。下标必须严格递增、不重复、不越界，且该词和词 58 都不能位于 `drop`；删除区本身已有边界，不再写 `split_after`。它不负责字幕断句。

相邻保留词之间的停顿另做逐项功能裁决。`expression_review.json.pause_candidates` 可用较低声学门槛发现候选，但门槛只负责“提醒听审”，不负责“自动删除”。只有听审确认为无效等待才可 `compress`；思考、强调、情绪、转折、动作、呼吸和句间功能必须 `retain`。建段器不再依据全局秒数自动压缩停顿，后置合并也不得撤销已审批的停顿刀口。

## 内容取舍四层

按以下顺序审阅，不使用删除率配额：

1. **机械错误**：口吃、重复启动、说错重说、半截话、无效前摇。
2. **信息冗余**：同一观点的弱版本、重复解释、重复案例、无新增信息的确认。
3. **主线价值**：与目标受众、核心结论和视频目标无关的旁枝。
4. **表达强度**：在多个可用版本中保留更具体、更有冲突、更有证据或更易理解的一版。

删除一段内容前同时回答：

- 删后主线是否仍能理解？
- 它是否提供前文没有的新信息、证据、情绪或信任？
- 它是否是后文成立所必需的前提？
- 同一作用是否已有更强的片段承担？

任一删减造成指代断裂、因果断裂、问答断头或事实失真，都必须撤销或连同依赖关系一起重构。

## 口头语与犹豫的三态决策

每个候选使用三态而非二元词表：

- `drop`：无效启动、虚词口吃、密集重复确认、删后不损失真实语气。
- `retain`：设问/论断收束、真实思考、自我修正、强调或情绪节奏需要；必须写类别和理由。
- `fix`：声音存在但 ASR 错字或漏字，只修文本，不改变留删。

同一个词在不同位置可得到不同决策。“呃、嗯、呢、啊、对吧、这个”都没有全局默认答案。

这是跨类型的公共契约，不得覆盖子技能的更具体默认。`single_speaker` 必须继续读取“单人口播粗剪”：对长时间卡顿和独立、无功能的“嗯”“啊”采用默认删除；其他口语仍按人物、情绪、命题修正与承接功能判断。该默认不外推到学员采访或未支持类型。

## 爆点前置与节奏递进

先给每个保留语义单元标注作用，再排顺序。Hook（开场钩子）类型保持开放，可来自冲突、结果、反常识、痛点、承诺、具体场景、身份反差、问题或情绪。

先比较“完整主张”与“短爆点”各自承担的功能。若短爆点只是把后面的完整前提提前重复一遍，而完整前提本身已经快速、可信且能自然带入正文，应直接使用完整前提，不为爆点前置制造一次无效复现。

可前置的爆点必须同时满足：

- 独立听懂，不依赖尚未出现的专名或指代。
- 有冲突、收益、风险、结果或认知落差。
- 强但未闭合：给出足够价值，又留下自然的信息缺口。
- 正文能够兑现，不是标题党。
- 移动后不篡改因果与时间事实。

开场不固定为 5–10 秒，也不固定输出三版。先在 `content_plan.json` 比较候选；采访多条模式还要先冻结 `portfolio_plan.json` 的整组主题边界，再由 `structure.json` 把当前选中候选映射到精删后的完整段。原有顺序终版不能提供前置真值；C2637 只证明“条件成立时可以前置与复现”，不提供固定时长、固定条数或固定模板。当前素材若重排，必须独立证明语义完整、因果不变且正文能兑现。

节奏递进不按固定秒数制造刺激。相邻片段应至少推进一种状态：

- 信息：提出问题 → 给判断 → 给原因 → 给证据 → 给做法。
- 冲突：常识 → 反例 → 新解释。
- 情绪：焦虑/不满 → 看见症结 → 获得确定性。
- 信任：结论 → 经历/案例 → 限定条件。

若连续两段只是在换说法、没有任何状态变化，合并或删去较弱者。身份介绍只在建立信任或理解背景所必需时前置；否则后置或删除。

同义内容散落在不同原文件时，要比较哪一遍能连续承接下一层论证。选择的是“整条链中最合适的一遍”，不是孤立看最短、最早或最强的一句。后一遍已经把一个主题自然讲进结论时，原则上不要再返回前一份素材的弱版本。

### 爆点的条件式复现

开头用过的原声不是一律从正文删掉，也不是一律保留。逐条回答：

1. 它在开头承担什么功能：结果、矛盾、反差还是问题？
2. 它回到正文时承担什么不同功能：恢复上下文、完成因果、承接后文还是兑现情绪？
3. 删掉正文那次后，观众是否仍能正确判断人物观点并理解后续？

只有第 3 题答案为“不能”，才在 `structure.json.intentional_repeats` 记录两次功能和 `deletion_impact`。脚本只允许该 Hook 连续片段恰好出现两次，第一次是开头前缀，第二次在正文；第三次或未登记重复均失败。不能以“首尾呼应好看”代替理解影响。

## 逐切口听审

粗剪刀口只有四个合法来源：真实删除内容、压缩影响节奏的停顿、结构重排、
或经内容决策显式写入的 `split_after`。不得为了“每段不超过几秒”、字幕换卡或
单纯增加刀数而切；这些都不是粗剪内容变化。两个相邻段若最终只删掉 0–3 帧，
且没有 drop / `split_after` / 重排边界，应还原为一个连续源片段。

每个真实刀口先保证末词韵尾和衰减完整，再保留一小段安静尾部。C2897 这个
证据家族中，用户明确指出 1 帧尾柄会导致尾音卡顿；70 个同名可对照片段里 47 个
向后调整，排除大段内容变更后，可靠补尾的中位数约 0.183 秒。这证明“必须留出
完整衰减和小段安静余量”，不证明所有切口都能无条件多取同样帧数。若下一个
发音或被删词更早到来，必须优先不包回声音，并把余量不足的边界交人工听审。

C2897 第二轮直接比较“改进后的 AI 第2版 → 用户精调第2版”：65 个原片段全部保留，
用户新增 1 个片段；只有 18 个原片段改了源边界。12 个段尾继续后放，正向改动中位
仍是 11 帧（约 0.183 秒，范围 5–28 帧）；7 个段头向后收，1 个原段尾因换用后一遍
自我修正而缩短。其余大多数边界不动。这证明默认 11 帧是生成起点，不是第二轮再
给全片统一加 11 帧；精调应集中在真实有问题的少数刀口。

第二轮还证明边界微调可能同时改变口头语与句法：用户补回“做成一个什么呢”中的
设问和“不重要的什么呢”中的自我修正，并删掉“了，总之”里的残尾“了”。因此，
比较 XML 时必须把源区间重新映射到词轴和音频；Final Cut 的 clip name 会沿用旧名，
不能拿它判断实际说了什么。该样本中新增片段甚至沿用了前一片段名称。

完成上述反馈学习、半词修复、粗剪重新冻结和基础字幕包装后，用户于 2026-08-10 对最终交付
给出“这个产生的结果就蛮不错的”的整体正向评价。因此，本证据家族可确认的不是某个固定
补帧参数，而是这套顺序在 C2897 上形成了可接受结果：少切无效刀口 → 局部保全尾音 →
按真实语义保留或删除口头语 → 读取人工反馈 XML 的真实源区间 → 必要时退回粗剪修正并重新冻结 → 再做字幕包装。
这是一条素材的一次完整链路验收，不等于用户逐刀、逐卡确认，也不能替代新素材听审。

DSCF2925 的“AI 第4版 → 用户精调版”补齐了另一个工程缺口：旧建段器以
“词轴末尾 + 11 帧”作目标，但真实韵尾/VAD 衰减常比词轴更晚，所以一些刀口在
真实声音后只剩 0–2 帧。AI 版 28 段的声学尾部余量中位约 47ms，10 段疑似切进声音；
用户版 40 段中位约 189ms，同类疑似仅 1 段。因此生成目标改为：以“词轴末尾”和
“真实声学衰减尾”中更晚者为起点，再预留约 11 帧；段头默认从真实起音前预留约 2 帧。
两者都只允许到达安全上界，不得越过被删声音、下一发音或素材边界。统计用于暴露旧算法
的系统性偏紧，不是要求每段都复制用户的具体帧数。

### 用户精调 XML 的两个入口

先问清用户交来 XML 的目的，不能把两种授权混在一起。

**反馈改刀入口**：用户明确要求理解、学习并继续优化粗剪。此时先做“源时码 → 真实声音 → 决策文件”的反向校验，再回到粗剪阶段：

- 校验素材身份、时间线顺序与项目画幅；包装元素不能混进粗剪基准。
- 逐段比较源区间，区分补尾、收头、换取材、拆段、合段和新增内容。
- 用真实音频判断词头与口头语；clip name 只作定位提示，不作转写真值。
- 若人工边界与未对齐的 drop 词旧时码冲突，必须绑定该 XML 的 SHA-256，并以独立
  ASR 或听审证明具体词没有残留；只对这些词写 `boundary_exceptions`。
- 发现半个词必须退回粗剪修正。C2897 第二轮把“图片”的“图”误切后，两套 ASR
  都把拼接识别成“是不骗”；包装前恢复了 24 帧词头。人改 XML 是最高优先级证据，
  但不是取消声学自检的理由。
- 重新生成并冻结所有受影响的 `keep`、词轴、段、结构和切口审阅，旧锁立即失效。

**只加字幕入口**：用户明确说人工粗剪已经完成，只需加字幕。此时 XML 本身是不可改基准；ASR、修字、断句与字符级对齐只服务字幕，不获得改刀权限。发现半词、错刀或属性冲突只能报告，不得静默修复。生成器只新增字幕及必要 effect，移除新增节点后完整结构指纹必须与输入一致。该入口直接进入包装，不重建 `segments / structure / rough_segments / cut_review`。

结构脚本完成后先生成真实切口清单：

```bat
"%PY%" "%BASE%\脚本\p2b_生成切口清单.py" <工作目录>
```

脚本生成 `kbcg-xgz/cut_review@2`。`segments` 按最终播放顺序覆盖每一段，
不只是有删接的切口；`cuts` 只记录中间删过声音、发生重排，或由显式 `split_after`
强制建立的真实边界。普通连续机械拆片不进入 `cuts`，但它们作为最终段仍必须审头尾。
脚本拒绝覆盖旧文件，Agent 必须真实播放后填写：

```json
{
  "schema": "kbcg-xgz/cut_review@2",
  "segments": [
    {
      "key": "L01.2",
      "head_preroll_frames": 2,
      "tail_release_frames": 11,
      "head_margin_exception": "",
      "tail_margin_exception": "",
```

若没有真实切口，`cuts` 保持空数组，但 `segments` 仍必须覆盖全片，且仍必须如实填写
review；不能因为 `cuts` 数量为 0 就省略头尾听审。余量低于默认目标并不自动失败，
但必须在对应 `*_margin_exception` 中说明安全上界。

每个切口至少确认：

- 词头、辅音和韵尾没有被截断；前一段没有残留下一词的尾音。
- 被删口头语、重复词、呼吸或其他说话人的声音没有被边界重新包回。
- 两段拼接后指代、语气、因果和情绪仍自然；不得靠字幕改写掩盖听感。
- 视频切口可以与字幕断点不同，但字幕逐字对应实际播放声音。

不得为满足目标余量越过下一个发音、被删词或素材尾。生成器可以用证据定标的默认目标，
但它只是安全上限内的起点，不能代替每个切口的实际发音判断与人工听审。

所有真实切口和 `expression_review.json` 都完成后，`keep.review.scope` 必须包含 `content_plan` / `keep` / `structure` / `cut_review`（采访再加 `speaker_turns`），然后运行统一 F1 入口：

```bat
"%PY%" "%BASE%\脚本_win\pipeline.py" f1 <工作目录> [--force]
```
（等价 macOS 原版的 `zsh 脚本/f1_粗剪验收冻结.sh`；Windows 上不要直接调 sh。）

只有粗剪锁有效后才写 `cards.json`。

## 粗剪自检

- 所有保留音频都来自源素材，文本没有越过 `fix` 通道被改写。
- `content_plan.json` 已先于 `keep.json` 审阅，目标、主题块、开头候选和所选主线可追溯。
- `topic_blocks` 逐词覆盖全素材，`selected_story` 与所有 selected 块完全一致，`selected_hook` 已引用合法候选。
- 所有被删词的音频都没有被段合并重新包回。
- 每个发现到的疑似口头语都在 `expression_review.json` 中逐项听审并明确为 `drop`、`retain` 或 `not_micro`；词轴外残声也已分类且没有未修复的有意义漏字。
- 每个保留段都能说明其结构作用；没有“因为说了所以留”的段。
- 最终顺序中普通保留段恰好一次；只有已记录开头/正文不同功能和删除影响的 Hook 片段可恰好出现两次。
- 开场能兑现正文，不依赖未解释的指代，也没有把结论全部说完导致后文失去动力。
- `cut_review.json.segments` 按播放顺序覆盖全部最终段，实测头尾余量、完整性、
  备注和低于目标的安全上界例外都已审阅。
- `cut_review.json.cuts` 只覆盖真实删接/重排/显式分段切口，已连续播放检查吸住、
  弹断、吞字、跳气口和被删声音残留；源时码连续的机械拆片没有被误算成删接。
- 粗剪冻结后才能进入字幕与包装；任何词轴、留删或顺序变化都必须让旧锁失效。
