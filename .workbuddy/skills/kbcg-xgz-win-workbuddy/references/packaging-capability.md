# 包装组件能力与授权边界

本文件只回答两件事：用户授权了哪些包装组件；当前交付器是否真的能稳定生成并验收这些组件。它不提供粗剪、字幕修字或字幕对齐权限。

## 一、基础交付不等于完整包装

`p4f_出FCPXML.py` 与 `p4j_出剪映草稿.py` 的基础职责是：读取冻结粗剪和既定字幕，套用当前平台与精确画幅的基础字幕 profile，再生成可导入工程。

下列组件不因为用户说“完整包装”就自动出现：顶部标题、重点上色、概念大字、编辑批注、音乐、音效、全局调整、局部画面强调、转场。每项都必须同时满足：

1. 用户已授权；
2. 有结构化决策或明确输入素材；
3. 当前平台有确定的工程表达；
4. 有对应结构与视觉/听觉验收。

缺一项即不得声称该组件已完成。

## 二、当前自动化能力矩阵

| 组件 | Final Cut XML | 剪映原生草稿 | 规则 |
|---|---|---|---|
| 基础字幕 | 稳定 | 稳定 | 只读 P2/P3/P4 真值 |
| 稀疏重点上色 | `final_cut_packaging.json` 显式登记后生成 | `jianying_packaging.json` 显式登记后生成 | keyword 只是候选；密度不超过 6% |
| 顶部标题 | `final_cut_packaging.json` 显式登记后生成 | 当前基础交付器不自动生成 | 不得读取 `captions_plan.title` 自动上屏 |
| 概念大字/编辑批注 | 基础交付器不自动生成 | 基础交付器不自动生成 | 需要独立实现与验收 |
| 音乐/音效 | 基础交付器不自动生成 | 基础交付器不自动生成 | 需要明确音频素材、混音和淡入淡出验收 |
| 调整层/局部画面/转场 | 基础交付器不自动生成 | 基础交付器不自动生成 | 需要平台原生节点或已验证工具链 |

## 三、Final Cut 显式包装清单

需要重点上色或顶部标题时，在工作目录写 `final_cut_packaging.json`：

```json
{
  "schema": "final-cut-packaging@1",
  "delivery_branch": "final-cut",
  "highlight_cards": [
    {
      "si": 0,
      "card_index": 1,
      "text": "这一张完整基础字幕",
      "keyword": "重点词",
      "reason": "章节核心命题，值得形成记忆点"
    }
  ],
  "top_title": {
    "text": "中文顶部标题",
    "reason": "用户授权的开场命题"
  }
}
```

`text` 必须与当前字幕卡完全一致，`keyword` 必须真实存在于该卡，`reason` 不能为空。未提供文件时，Final Cut 只输出纯白基础字幕；未提供 `top_title` 时不生成顶部标题。

## 四、完整包装交付报告

报告必须逐项写“已生成并验收 / 用户未授权 / 当前工具链不支持，待人工补齐”。禁止使用一句“已完成包装”覆盖不同状态。基础 XML、DTD 或剪映工程结构通过，只能证明基础交付通过，不能证明音乐、音效、概念大字或视觉效果完成。
