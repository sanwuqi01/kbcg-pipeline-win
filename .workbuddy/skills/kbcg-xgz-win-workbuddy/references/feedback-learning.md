# 用户精调 XML 学习闭环

用户在 AI 交付上继续精调后，AI XML 与用户 XML 构成同一素材家族的一次反馈。学习的对象是“用户实际改了什么”，不是把用户没有改到的部分全部认定为偏好。

## 固定顺序

```text
锁定 AI 版与用户版路径和 SHA-256
→ 按真实素材引用与源区间做结构化差异
→ 将差异路由到 P0–P6
→ 结合原音/画面解释原因
→ 只更新发生问题的工序规则
→ 同步样本 scope 与回归用例
→ 用新素材前向验证
```

运行：

```bat
"%PY%" "%BASE%\脚本\l1_学习用户精调XML.py" <AI版.fcpxml或fcpxmld> ^
  <用户版.fcpxml或fcpxmld> --output <feedback_diff.json>
```

脚本只生成证据报告，不自动修改 Skill。报告中的分类是定位线索，不是审美结论：

- P0：项目 format、画幅或帧率声明；
- P1：所选素材、源区间、顺序、重复、段头段尾和刀数；
- P2：基础字幕文字、卡片数量与断句；
- P3：同一张字幕的出现、切换和结束时码；
- P4：字体、字号、基础颜色和位置；
- P5：标题、重点色、音乐、音效与其他包装节点；
- P6：XML 版本、资源引用和工程结构。

字幕学习不得直接比两版成片绝对时间线：P1 多留一段内容会让后面所有字幕整体平移，但这不是 P3 对齐错误。同文逻辑卡必须回到原素材起音锚比较，同时兼容 Final Cut 剪短 title 后保留的 `title.start`。同文、同样式且在视频刀口两侧时间线连续的 title 要合并为一张逻辑卡，但保留多个 source fragment 供审计。末卡结束受 P1 段尾控制，不应在 P3 重复扣分。

如果用户只精调到成片中的某个时间点，必须把反馈拆成“已确认前缀”和“待续写后缀”：

```text
锁定用户 XML 哈希与精调终点
→ 原样回灌已确认前缀字幕
→ 只在后缀重新做语义分卡和声学对齐
→ 对前缀文本、顺序、起点生成回归哈希
→ Final Cut / 剪映共用这份锁，不得在平台序列化时重做字幕
```

使用 `p3u_续接用户精调字幕.py` 时，后缀必须提供显式语义分卡；脚本会拒绝拆开
多字 ASR token、拒绝漏掉仍保留的声音，并把 `captions_plan`、续剪计划和用户前缀
回归记录一起写入交付锁。这样“学过一次”不再只存在于文档，而会在后续生成漂移时直接失败。

参与规则开发的样本只允许运行 `l2_训练回归评分.py`，结果标注为 `in_sample_regression`；它能证明已知问题没有回归，不能证明新素材泛化。要声称稳定，必须在生成时禁止读取目标用户 XML，冻结产物后才打开参考评分，并至少用 3 个未参与规则开发的同类新素材做前向验证。

## 证据边界

- `clip name` 可能是陈旧 ASR 元数据，不能代替真实声音。
- XML 只能证明工程差异；尾音、呼吸、漏字和语气功能必须听原音。
- 音频删留、基础字幕、包装文字是三层真相，不能相互反推。
- 同一原素材的多轮修订与一条拆多条都只算一个 `evidence_family_id`。
- 用户 XML 是最高优先级反馈，但仍可能保留旧问题；只学习用户实际改动，并继续跑独立声学/工程验收。
- 单个样本只能产生候选规则；用户明确解释或多个独立家族同向出现并通过前向测试后，才能升为通用规则。
