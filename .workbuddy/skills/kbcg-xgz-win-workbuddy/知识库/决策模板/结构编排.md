# 粗剪结构编排

## 作用边界

本层放在 `content_plan.json`、`keep.json` 和 `p1_建段.py` 之后，只把已选主线映射为已保留语义段的播放顺序。运行：

```bash
python3 脚本/p2_结构编排.py <工作目录>
```

输入为 `content_plan.json`、`segments.json` 和人工/语义决策层写的 `structure.json`，输出为 `rough_segments.json`。脚本只做确定性校验和整段投影，不代替语义判断；绿色通过只证明字段和映射一致。

硬约束：

1. `segments.json` 是 p1 已经完成留删后的全部保留段；`sequence` 必须覆盖全部段。普通段恰好一次；只有符合“开头与正文功能不同，且删掉正文复现会损害观众判断或理解”的 Hook 片段，才能在 `intentional_repeats` 中登记并恰好出现两次。
2. 每个 Hook 候选用 `candidate_id` 标识，可以引用一个或多个完整段。`selected_hook` 必须是其中一个 `candidate_id`；所选候选的全部 `segment_ids` 必须按声明顺序完整占据 `sequence` 前缀。
3. 只能重排完整段。不得在 `structure.json` 里写 `text` / `in` / `out` / `words` 等媒体字段，不得改写、拼句、拆句或发明任何声音。
4. 如果一个 p1 段本身不是完整语义单元，回上游重做留删/建段；不得在本层通过改字或改时码修补。
5. `goal` / `audience` / `main_claim`、Hook 候选和主线方向必须继承已审阅的 `content_plan.json`；若要改变，先更新内容地图，不得在本层另起一套目标。
6. `structure.json.selected_hook` 必须与 `content_plan.json.selected_hook` 完全一致；对应的 `candidate_id` 不得改名，Hook 段的全部词下标必须落在该候选 `block_ids` 所覆盖的词区间内。
7. 除 Hook 前缀、Hook 回到正文和已登记复现外，任何源时序倒退都必须在对应 `sequence` 项登记 `source_order_exception`，不能只用普通 `reason` 掩盖误排。

## `structure.json` 格式

段 ID 优先使用 `segments.json` 的 `segment_id`；现有 p1 产物没有该字段时，使用其整数 `part`。类型必须一致：整数 `1` 不等于字符串 `"1"`。

```json
{
  "goal": "让小团队判断什么时候值得引入 AI 工具",
  "audience": "没有专职技术团队的业务负责人",
  "main_claim": "先从高频且可验收的任务开始，不要从工具清单开始",
  "hook_candidates": [
    {
      "candidate_id": "投入越多反而越忙",
      "segment_ids": [3, 1],
      "hook_type": "矛盾加追问",
      "strength_reason": "第一段直接命中投入越多反而越忙的损失",
      "open_loop_reason": "第二段把矛盾收窄为具体问题，但答案仍在后续"
    }
  ],
  "selected_hook": "投入越多反而越忙",
  "intentional_repeats": [
    {
      "repeat_id": "hook-back-in-body",
      "segment_ids": [3, 1],
      "opening_function": "用损失和追问建立未闭合问题",
      "body_function": "恢复原上下文并承接后续解法",
      "deletion_impact": "删掉会让观众无法判断解法针对的具体问题"
    }
  ],
  "sequence": [
    {
      "segment_id": 3,
      "role": "hook",
      "reason": "用未闭合矛盾建立问题"
    },
    {
      "segment_id": 1,
      "role": "hook_question",
      "reason": "把矛盾收窄为未闭合的具体问题"
    },
    {
      "segment_id": 0,
      "role": "problem_scope",
      "reason": "补入回答问题必要的背景"
    },
    {
      "segment_id": 2,
      "role": "main_claim",
      "reason": "回答开场问题，给出主张"
    },
    {
      "segment_id": 3,
      "role": "body_reprise",
      "reason": "回到原论证现场"
    },
    {
      "segment_id": 1,
      "role": "body_reprise",
      "reason": "补全后续解法所需前提"
    }
  ]
}
```

`role` 和 `hook_type` 不设枚举，可以根据素材自定义。一个 Hook 可以由多个连续播放的完整语义段共同完成，但不能拆分任一段。

`intentional_repeats` 默认缺省或为空数组。每组必须：

- 只引用 `selected_hook.segment_ids` 中保持原顺序的连续片段。
- 分别写清 `opening_function`、`body_function` 和 `deletion_impact`；“首尾呼应”不是有效删除影响。
- 在 `sequence` 开头先作 Hook 前缀播放一次，再在正文以相同顺序连续播放一次；不允许第三次。
- 字段只是对例外的可审计登记，不是复制任意音频的授权。

p2 的底层解析器仍可能读到旧单段格式，但当前完整决策契约要求 `structure.selected_hook` 与 `content_plan.selected_hook` 的字符串 `candidate_id` 完全一致；旧的整数 `selected_hook` 不能进入新工作流。新决策统一写 `candidate_id + segment_ids`。

`sequence` 的额外注释字段会被保存到输出段的 `_rough_structure`，但任何文本、时码或词轴字段会直接导致硬失败。

`source_order_exception` 只允许出现在“当前段源顺序小于前一播放段”，且该倒序不属于 Hook 前缀、Hook 回正文或登记复现时。三个字段都必须具体：它为什么需要倒序、怎样保证不歪曲事实、这个切口实际听审了什么。没有倒序却滥填该字段同样硬失败。

```json
{
  "segment_id": 5,
  "role": "evidence",
  "reason": "在方法之后补入较早发生的反证",
  "source_order_exception": {
    "editing_function": "先给方法，再用前面的具体矛盾作反证",
    "truth_boundary": "不改变事件先后、人物立场和因果",
    "listen_check": "逐切口确认尾音、词头与语义自然"
  }
}
```

## 决策步骤

### 1. 从内容地图映射主张与 Hook

先核对 `content_plan.json` 的 `goal` / `audience` / `main_claim` / `selected_story` / `selected_hook`。其中 `selected_story` 已恰好覆盖全部 `decision=selected` 的内容块，Hook 候选以 `block_ids` 指向内容块；本层再把这些词区间映射到精删后的 `segment_ids`。不知道要让谁产生什么理解或行动时，退回内容地图；“爆点”只是大声或夸张，不是结构决策。

候选 Hook 必须同时满足：

- **强**：对目标观众立即显示明确的收益、损失、矛盾、惊讶或情绪力。
- **未闭合**：打开一个具体问题或紧张关系，答案在后续段。
- **单元完整**：不通过砍掉前半句、改写口播或拼接不相邻字词人造悬念。

一个已经把原因、结论和方法全说完的强句，可以是重点，但不一定是开场 Hook。`strength_reason` 和 `open_loop_reason` 必须分开写，防止把“语气强”误当“有结构张力”。

Hook 类型开放：案例结果、问题、矛盾、细节、身份反差、情绪、预告或其他能完成上述任务的完整单元都可以；不限于吐槽、“爆点”或颠覆句。

原有 15 份顺序终版不能当 Hook 搬运模板；C2637 只证明爆点前置与正文复现可以在条件成立时使用，不证明固定长度或每片必须复现。若当前素材选择重排，必须在 `reason` 中说明原时间/因果是否受影响、前置后指代是否独立、正文如何兑现。

### 2. 身份介绍只服务信任缺口

只在主张依赖特定经历、资质或亲历证据，且目标观众此时仍有信任缺口时，保留或提前身份介绍。

- 身份本身就是反差/证据，且能强但未闭合地打开问题：可以作 Hook。
- 身份只用于解释“为什么值得信”：放在 Hook 之后、第一个需要信任的主张之前。
- 去掉身份不影响理解和信任：应在 keep 内容层删除，不应由 p2 通过遗漏段伪装删除。

### 3. 用状态变化组织节奏

不设“每 15–20 秒一个刺激”的定时器。对每个相邻段，在 `role` / `reason` 里说清它相对前一段造成的状态变化：

- 信息：问题→主张、抽象→具体、结论→机制。
- 情绪：平静→惊讶、焦虑→释然、严肃→幽默。
- 信任：主张→案例、案例→数据、质疑→回应。
- 冲突：常识→反例、方案→代价、目标→障碍。

只要有一个状态发生有意义的变化，段落就可以继续；不要为了频率硬插与主张无关的金句。如果相邻两段在信息、情绪、信任和冲突上都无变化，先尝试与其他完整段换序；仍无改善则回 keep 层重新判断它是否必须保留。

### 4. 完成前自检

- `sequence` 覆盖全部保留段；普通段恰好一次，已登记 Hook 复现段恰好两次；内容取舍只在 keep 层做。
- 开头前缀正是 `selected_hook` 的全部 `segment_ids`，数量与顺序都一致，Hook 前没有例行自我介绍。
- Hook 同时具备强度、未闭合性和语义完整性。
- 身份介绍有明确信任任务，不是按模板保留。
- 每个相邻段至少改变信息/情绪/信任/冲突中的一项，没有定时刺激要求。
- 没有未登记复制或改写口播文本；复现组的两次功能和删除影响均具体可审计。
- 每个非 Hook/复现倒序都登记了 `source_order_exception`，说明不出来的倒序已回退重排。
- 结构与 `content_plan.selected_story` 一致；任何偏离已经回上游重新审阅。
- `goal` / `audience` / `main_claim` / `selected_hook` 与内容地图完全一致，Hook 段没有越出候选块的词区间。

完成 p2 后立即生成听审清单：

```bash
python3 脚本/p2b_生成切口清单.py <工作目录>
```

该脚本枚举相邻 `out_f != in_f` 的删接/重排切口，也纳入由 `keep.split_after` 显式建立的源连续边界，并将四项检查初始化为 `false`。逐项播放后在 `cut_review.json` 确认尾音完整、词头完整、无删词残留、语义自然，填写非空 `notes` 和完整 review；不得批量填 `true`。粗剪必须依次通过 p1q、freeze、verify 后才进入字幕卡。

## 输出不变式

`rough_segments.json` 保持与 `segments.json` 一样的数组形态。每个元素是源段的深拷贝，`text` / `in` / `out` / `words` 等字段原样保留，只增加 `_rough_structure`：

```json
{
  "_rough_structure": {
    "segment_id": 3,
    "source_order": 3,
    "sequence_order": 0,
    "role": "hook",
    "reason": "用未闭合矛盾建立问题",
    "selected_hook": true,
    "hook_candidate_id": "投入越多反而越忙",
    "hook_segment_order": 0,
    "playback_key": "L01.3",
    "intentional_repeat": true,
    "repeat_group_id": "hook-back-in-body",
    "repeat_occurrence": 1,
    "body_reprise": false
  }
}
```

这些字段只记录结构决策，不参与生成声音或修改源时码。复现段的第二次播放使用唯一 `playback_key`，例如 `L01.3@2`，供切口听审和字幕卡分别对账。
