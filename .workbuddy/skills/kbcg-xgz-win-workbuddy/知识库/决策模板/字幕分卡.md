# 字幕分卡决策

## 输入与输出

只有 `cut_review.json` 已逐项听审且 p1q → freeze → verify 完成后，才只读最终播放顺序的 `rough_segments.json` 写 `cards.json`。不得在粗剪锁之前写卡，也不得针对源顺序 `segments.json` 先写卡后再重排。

每个段键来自 `rough_segments.json._rough_structure.playback_key`；普通段形如 `L01.3`，同一 Hook 片段在正文有意复现时，第二次形如 `L01.3@2`。旧产物缺 `playback_key` 时才回退使用 `line.part`。键必须与 `rough_segments.json` 全等：不缺、不多、不重复。两次播放要分别写卡，因为它们在不同上下文中的字幕节奏和强调可以不同。

新格式只有两个字段：

```json
{
  "L01.3": [
    ["很多人用上AI", "AI"],
    ["反而变得更忙", ""]
  ]
}
```

- 第一个字段 `text`：对齐文本。该段所有卡的 text 依序连接后，必须与段文本逐字符一致，包含英文专名内部的真实空格。
- 英文专名内部的真实空格必须保留，例如 `Claude Code`；空格不产生声学时码，但参与屏显和字符位置映射，不能静默压成 `ClaudeCode`。
- 第二个字段 `keyword`：可选语义关键词候选，必须是本卡 text 的子串；无候选写空字符串。它不直接决定成片上色；剪映重点字幕必须在 P5 另建显式稀疏清单。
- 不再提供 display（显示改写/隐藏）通道。
- 兼容旧三元 `[align, display, keyword]` 时，display 只能为空或与 align 相同；删字、改字、重排一律失败。

ASR 错字只在 `keep.json.fix` 修。仍在播放的口头语必须照实显示；不想让观众听见或看见时，回 `keep.drop` 连声音一起删。

## 基础字幕与包装文字分层

`cards.json` 只描述基础字幕，也就是保留口播的文字真值。开场命题、概念大字、拟声文字、人物口吻提示和编辑批注不进入 `cards.json`，也不能通过 `keep.fix` 冒充说话人原话。

完整包装里允许同一时刻存在两层文字：基础字幕回答“他说了什么”，包装标题回答“这一刻要观众记住什么”或“编辑怎样解释这个包袱”。两层必须使用不同的工程角色、标题命名或 lane（轨道）职责，并分别验收：

- 基础字幕连接后仍须与保留声音逐字符一致；
- 概念强调若复用了口播原词，不得替换或挤掉基础字幕；
- 编辑批注即使贴着发音出现，也不参与 ASR、断句和字符级时码覆盖统计；
- 不能从“包装大字写了什么”反推声学识别结果。存在疑问时回听原声。

## Subtitle bridge（字幕桥接）

视频切口解决声音留删和画面连续性，字幕断点解决观众阅读；两者可以解耦。若两个 `rough_segments` 在删接后共同组成一个完整句子，可以把切口两侧设计成同一语义卡的 bridge：

- 先决定整句的句法断点，不因为视频换片就强制断字幕。
- `cards.json` 仍把左右文字分别登记在各自真实播放的段中；FCPXML 生成时才把经审核的左右末/首卡合成一张可跨切口显示的 title，原卡与字符时码保留作审计。
- 每个字使用其实际发音的字符级时码；不得让后段文字在前段抢跑，也不得用前段文字覆盖后段声音。
- bridge 不能修复半个词、尾音残留、指代断裂或不自然拼接；发现这些问题必须退回粗剪逐切口处理。
- 被 bridge 消费的左右端点最终合成一张字幕，最短卡闸门按合并后的显示卡判断；不得因为单独的“的、他、你”等端点很短就拒绝一个语义完整的合法桥接。

因此“不从下一视频段借词”仍是硬规则；bridge 是语义与视觉连续，不是文字跨源片段搬运。

需要 bridge 时，前段从简写数组升级为对象；`left_text` 必须等于本段最后一卡，`right_text` 必须等于下一段第一卡：

```json
{
  "L01.3": {
    "cards": [["因为流程没理顺", "流程"]],
    "bridge_to_next": {
      "left_text": "因为流程没理顺",
      "right_text": "所以AI才会反复出错",
      "reason": "删接两侧共同构成一个因果句，视觉连续但文字不跨媒体边界"
    }
  },
  "L01.4": [["所以AI才会反复出错", "AI"]]
}
```

`bridge_to_next` 必须且只能包含 `left_text` / `right_text` / `reason`，末段不得声明 bridge。两段各自的卡文本仍须分别与各自 `rough_segments.text` 完全一致。

## 断句原则

按以下优先级决定卡边界：

1. **语义完整**：一张卡承担一个可快速理解的意群。
2. **句法自然**：新卡从新的句法成分或新小句起点开始。
3. **不可拆单元**：不拆中文词、专名、英文单词、数字与单位、强依赖的数量/修饰结构。
4. **口语节奏**：设问、转折、自我修正和强调可以形成短卡，但不能只为“看起来有节奏”破坏句意。
5. **可读性**：字宽、单行和 CPS（每秒字符数）只作护栏，不先按字数切再补语义。
6. **声学定位**：AI 只决定在哪个字符边界断。段内换卡由 `p3_分卡.py` 以下一卡首字的强制对齐起音为主；若该时刻仍在静音、且半秒内独立 VAD 检测到真实开口，才允许向后钳到开口，防止字幕抢跑，不得跨长停顿改写语义断点。段首字幕单独处理：首字起音距视频切口不超过 2 帧时，首卡必须吸附切口，不能因四舍五入或 VAD 留下 1–2 帧“视频先走、字幕后出”的空档；只有首字明确晚于切口时才等待开口。

### 横版长字幕：单行连续换卡，不在卡内硬换行

DSCF2925 4K 横版的“AI 第4版 → 用户精调版”提供了直接字幕证据：
AI 版 228 张中最长卡为 15 个全角字宽，有 6 张超过 12；用户版 237 张的最长卡为 13，
没有超过 13，也没有一张基础字幕使用卡内换行。因此横版基础字幕仍保持单行，
13 个全角字宽是当前机器护栏；超过时必须回到语义和实际语气重切，不是等分字窗。

用户的实际重切包括：

```text
能否真的吃上AI的红利
→ 能否真的吃上 / AI的红利

按照你之前已经拿到结果的路径
→ 按照你之前 / 已经拿到结果的路径

很多人去搭建自己智能体的时候呢
→ 很多人去 / 搭建自己智能体的时候呢

当成一个你需要去培养的员工
→ 当成一个 / 你需要去培养的员工

我就要打个引号不一定真不一定
→ 我就要打个引号 / 不一定 / 真不一定
```

前四组分别在利益对象、时间/经验状语、新谓语和新实体说明前换卡；最后一组使用
连续短卡表达人物的自我强调。这些是不同句法决策，不能缩写成“每 7 个字切一次”。
若语义单元本身不可拆，应先完整保留并人工复核，不得为过机器护栏拆词。

连接词没有固定位置：

- “但是、所以、那么、然后”确实启动新意群时放卡头。
- 它与前句共同完成收束或承接时可以留前卡。
- 不允许根据词面规则一律独立或一律前置。

短卡也没有统一禁令：“但是”“是吧”等在明确的转折、反问或节奏停顿处可以单独成卡。反过来，短词若只是上句残尾，不得为了凑长度悬空。

C2637 的用户调整版证明，“第二”“OK”“员工”这类短卡可以是序数拍点、确认拍点或新主语起点；关键不是字少，而是它是否在当前句法和逻辑中开启了新意群。同理，“考过了 / 就是你学会了 / 考不过 / 就简单了”应按对照逻辑分拍，不按平均字数装箱。

## 严禁

- 不拆词或把上句残尾塞到下一卡开头。
- 不用基础字幕卡内换行掩盖过长文字；超过画幅护栏时回语义边界重切成连续卡。
- 不用 display 隐藏“呃、嗯、呢、对吧”等仍在播放的声音。
- 不从下一视频段借词，也不让任何有声音的段变成零字幕。
- 不把视频切口机械转换成字幕断点，也不把 bridge 当作隐藏错切的手段。
- 不用 jieba 或字数窗口静默代替语义分卡。
- 不在缺字符级时码时退回整段线性估算。
- 不为修正卡时长而让脚本自动合卡、丢关键词或改变用户写的断点。
- 不把开场命题、概念大字、拟声文字或编辑批注混入基础字幕真值。

## 操作步骤

1. 按 `rough_segments.json` 当前顺序读完整上下文。
2. 为每段标出意群、转折、设问、并列和不可拆单元。
3. 从句法边界切出卡，再用画幅/CPS 护栏复查。
4. 标记需要 subtitle bridge 的真实删接；逐字核对切口两侧的声音归属和字符时码。
5. 每段至少一张非空主字幕。
6. 连接所有卡的 text，与该段 text 逐段核对。
7. 确认粗剪锁未变，再运行终结器；它会校验 `cards.json` 的段键、逐段文本和 bridge 契约：

```bash
python3 脚本/decision_contract.py verify <工作目录>
zsh 脚本/finalize_fcp.sh <工作目录>
```

字幕失败回 `cards.json` 修；若发现内容或切口问题则退回粗剪重审、强制更新锁，不开 fallback。

## 自检示例

错误：

```text
他们自己在AI落地的 | 这个过程 | 当中
```

更自然：

```text
他们自己在 | AI落地的这个过程当中
```

错误原因不是卡长，而是第一种把紧密修饰关系和方位结构拆散。

错误：

```text
好你 | 拆开完之后
```

更自然：

```text
好 | 你拆开完之后
```

这里“你”启动新主谓结构，应成为新卡开头。

最终断点正确与否仍需结合实际语速和画面检查；技术闸门只能证明结构、覆盖和时码契约成立，不能代替用户观感。

## C2901/C2903 竖屏成片的断句修正

这组修正属于 P2 字幕文字，不得因此改粗剪或 P3 时码规则：

```text
但是唯一能让我记住 / 的话可能符合这么几点
→ 但是 / 唯一能让我记住的话 / 可能符合这么几点

我觉得他一定是 / 得有身份的
→ 我觉得他 / 一定是得有身份的

你想让别人记住你 / 整个人的整体
→ 你想让别人记住 / 你整个人的整体

不见得每一个小区 / 的保安他都会记住
→ 不见得 / 每一个小区的保安 / 他都会记住
```

共同原则是：断点落在新的谓语、判断、转折或独立意群之前；不把“的话”“的”“你”等强依赖成分悬在错误一侧。具体卡数不是模板。

同一成片还出现了转写修复，例如把误识别的“他先了女同”恢复为实际原声“他掀翻了男同学桌子”。这类内容先回听原声，再走唯一文字修正通道；“比喻翻车”等编辑批注属于 P5，不得写进基础字幕真值。
