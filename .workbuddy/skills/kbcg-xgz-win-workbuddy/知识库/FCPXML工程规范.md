# FCPXML 工程规范

## 生成边界

`p4f_出FCPXML.py` 是基础字幕工程的纯序列化层，只读取：

- `config.json`
- `rough_segments.json`
- `captions_plan.json`

它不得重新判断内容、切段、重排或修字。`rough_segments.json` 缺失时必须失败，不能回退读取源顺序 `segments.json`。

它通过不等于完整包装已经完成。音乐、音效、调整层、概念大字、编辑批注和局部画面处理属于粗剪锁之后的扩展层；只有用户授权并按“单人口播成片包装”复核后才能加入。

剪映不是另一套剪辑决策。`p4j_出剪映XML.py` 与 `p4j_出剪映草稿.py` 共用同一冻结结果，只转换平台载体；不得改变视频片段的源时码、顺序、时长、字幕文本或字幕时码。

## 平台分支

- 用户明确说 Final Cut、FCPXML 或 XML 时走 Final Cut；明确说剪映或没有说明平台时，正式交付默认为剪映原生草稿。只有用户明确要两份时才同时生成。
- Final Cut：主字幕为 lane 1 的 Basic Title，使用 Final Cut 已确认的字体、字号和 Position 参数。
- 剪映兼容 XML：视频仍为 spine 直接子级的连续 asset-clip；lane 1 主字幕转换为 `caption`，role 为 `caption.ITT.zh`，text placement 为 `bottom`，字号标定为 188（剪映界面约 8 号），且不保留 Final Cut Position 参数。
- 剪映原生草稿：项目素材库必须登记且只登记一份完整原片；所有视频片段仍引用同源原片并位于唯一视频轨，片段 `render_index=0`；所有字幕 material 类型为 `subtitle`、字号为 8，并绑定剪映“聚珍体”资源。素材库登记只属于最终封装，不得改变粗剪片段、源时码、顺序或字幕。
- 实机证据表明，剪映会把多种合法 FCPXML 主故事线导入到封面上一层并留下空主轨。XML 结构验收只能证明 FCPXML 主故事线合法，不能证明剪映界面真主轨；真主轨由原生草稿验收负责。
- C2897 第 3 版已在剪映专业版实机复核：视频与“封面”处于同一轨；点选字幕后面板显示“聚珍体”、字号 8，并可将文本样式应用到全部字幕。以后剪映正式交付必须同时保留结构验收和界面验收两类证据。
- 平台名必须进入交付文件名。Final Cut 与剪映 XML 不可互相改名冒充。

## 时间与顺序

- 内容决策与词轴内部可继续使用 60 fps 分析网格，但这不是交付帧率。
- 交付时间线必须使用原素材真实帧率；例如 `60000/1001` 必须保留为 59.94 系列帧率，不能改写成 60。
- 所有源时码、片段时长与字幕时码在交付前量化到原素材的真实帧网格；不得写入半帧或混合帧率时间。
- 每个 `asset-clip` 的 `start/duration` 来自 rough segment 的源帧。
- 每个 clip 的时间线 `offset` 必须与上一个 clip 严格相接。
- `captions_plan.segments_tl` 的段数和每段源 `in_f/out_f` 必须与 rough segments 完全一致。
- 主字幕挂在对应 clip 的 lane 1；每个有声音的 clip 至少一张非空主字幕。

## 素材属性

从实际源文件重新探测显示画幅、编码画幅、旋转、真实帧率、音频采样率和声道，并与 `config.media` 互相校验：

- 横版和竖版不得都硬写成 1920×1080；4K 不能降为 1080p，1080p 也不能被擅自放大。
- 手机竖拍可能以横向编码画幅加旋转元数据存储，项目应保持原文件与旋转关系，不能烘焙旋转或裁切。
- 单声道写 mono/1 channel；双声道写 stereo/2 channels。
- 项目 format 与 asset format 都必须按真实显示画幅和帧率声明，不能让软件替错误声明做隐式变换。
- Final Cut 已知标准横版格式必须写入官方格式 `name` 与经探测映射的 `colorSpace`，视频 asset 必须声明 `videoSources="1"`；竖版或其他自定义画幅不得伪造标准格式名。DTD 通过不能代替这组 Final Cut 语义验收。
- 素材含内嵌时间码时，`asset start` 必须映射真实时间码起点，每个 clip 的 `start` 与段内字幕 `offset` 同步进入该源坐标，`tcFormat` 必须与 DF/NDF 一致。不得把带时间码的相机素材一律写成 `start="0s"`。
- 素材文件必须存在；源路径变化会使决策锁失效。

这一段约束从原素材新建的工程。人工粗剪 XML 的“只加字幕”入口不得借技术标准修改用户既有工程；若既有项目 format 与源文件不同，保留原结构并把差异报告给用户。

## 人工粗剪 XML 只加字幕

用户明确表示粗剪已由人工完成，并交来 XML 只要求字幕时，该 XML 就是不可改的冻结基准。只允许新增字幕及其必要 effect 资源；不得重建、合并或修剪任何视频段，也不得改项目名、UID、format、素材、marker、`ref/offset/start/duration`、变速、转场、缩放或旋转。

生成后移除本次新增的字幕节点与字幕 effect，再对完整 XML 结构做指纹比较；必须与输入一致。发现半词或错刀只报告，不自动修复。若用户是在用人工 XML 反馈粗剪问题、并明确要求继续改刀，才退回粗剪阶段重新决策与冻结；这与“只加字幕”是两个入口，不能混用。

## 人工粗剪 XML 继续完整包装

只有用户明确授权“在这个粗剪上继续包装”时，才从严格只加字幕切换到本分支。输入 XML 仍是口播内容锚点：记录路径、SHA-256、项目 format、原素材和口播音频覆盖；不得重新选材或借包装改变冻结对白。

允许新增：

- 连接式开场命题、概念强调与编辑批注标题；
- 章节音乐、论证型声音证据和节点音效；
- 全局调整层、局部调整层、短时画面变换与章节转场；
- 为定格、缩放、透明度或局部效果而拆分视频/音频结构。

最后一项只改变画面表达，不获得改对白的权限。若视频节点被拆细或放入 clip 容器，口播音频的来源、范围、顺序和连续性仍须与冻结基准一致。无法安全表达的专有 effect、LUT（查找表）或第三方插件必须保留原节点或明确报告，不能用名称相近的效果冒充。

完整包装的结构比较不能沿用“删除字幕后 XML 全等”的只字幕指纹。应分别验收：项目技术属性不变、核心口播覆盖不变、包装节点为新增或非破坏性画面结构、时间线无意外空洞、对白可懂、DTD 通过。

## 字幕样式

Final Cut 主字幕样式的唯一可执行真相源是 `脚本/media_contract.py` 的画幅 profile，`p4f_出FCPXML.py` 与 `p4h_包装人工粗剪.py` 只消费它。下方数值用于说明本轮用户确认结果；若它与代码不一致，必须在 P4 内同步更新代码、验证器和本段记录，不能只改其中一份。

已确认的 Final Cut 基础字幕 profile 按精确画幅独立登记：1080×1920 竖屏为聚珍体 `XQjuzhentiZJSY`、字号 50、水平居中、X=0、Y=-220；3840×2160 横屏为同字体、字号 120、水平居中、X=0、Y=-478.53；2160×3840 竖屏 4K 为同字体、字号 52、水平居中、X=0、Y=-190，开启黑色投影，不透明度 75%、模糊 0.63、距离 2、角度 315°。它们只适用于 lane 1 基础字幕；开场命题、概念大字和编辑批注属于 P5。Final Cut 参数不按像素宽度线性缩放，未确认画幅停止生成。

修改样式时：

1. 只改 p4f 常量，不改粗剪与字幕文本。
2. 生成最小横版/竖版样例。
3. 运行 DTD 验证并在 FCP 中实际导入复核。
4. 区分主字幕与高级包装标题，不从大字卡反推主字幕参数。
5. 运行 `p4f_验收.py`，逐张验证 lane 1 的字体、字号、居中、Position 与当前画幅登记的投影字段；任一漂移即失败。

## 包装层职责

- **基础字幕**：口播真值，按画幅 profile 执行，逐字覆盖保留声音。
- **开场命题**：建立问题和观看理由；不进入字幕覆盖统计。
- **概念强调**：复用已说出的核心词形成记忆点；不能替代基础字幕。
- **编辑批注**：说明反差、自我修正或人物包袱；不是 ASR 修字。
- **全局调整层**：统一整片画面基线，优先使用少量贯穿式结构。
- **局部调整/画面组件**：只服务具体语义节点，需要时与对白音频解耦。
- **声音层**：对白优先；章节音乐、声音证据、节点音效依次加入，并逐处检查音量、EQ、淡入淡出和对白遮蔽。

包装节点不设固定数量、固定间隔或固定音效清单。它们由语义章节决定。

## XML 结构硬约束

- 从原素材新建的文档当前输出 FCPXML 1.11；人工粗剪 XML 只加字幕时保留输入版本，不允许为统一版本重写工程。
- 所有 `id` 全文唯一。
- 元素顺序符合 Final Cut Pro 自带 DTD。
- 文本、属性和素材 URL 正确转义。
- 标题 text-style 引用必须存在且唯一。
- sequence duration 等于所有 clip duration 之和。
- 最后一张主字幕结束于所属 clip 末尾，卡间不留无字幕空洞。

## 终检

运行：

```bash
python3 脚本/p4f_验收.py <输出.fcpxml>
```

终检必须同时确认：

1. XML 可解析。
2. clip 连续、帧网格正确、sequence 时长一致。
3. 每个 clip 的主字幕覆盖完整。
4. ID 唯一、素材存在。
5. 项目与 asset 的帧率、画幅、色彩空间、标准格式名和媒体源声明与实际素材一致。
6. 与 XML 根节点版本一致的 Final Cut Pro 官方 DTD 实际执行并通过；新建工程当前为 1.11。

完整包装还必须人工或通过专用审计确认：冻结对白覆盖未改变；基础字幕与包装文字分层；全局与局部画面处理没有误伤对白；音乐、声音证据和音效没有遮蔽主信息。基础 `p4f_验收.py` 不证明这些项目已通过。

找不到 DTD、DTD 未运行或任何检查失败，都不能报告“终检通过”。

剪映分支另运行：

```bash
python3 脚本/p4j_验收.py <剪映输出.fcpxml>
```

XML 除通用时间线与 DTD 检查外，还必须确认：spine 只有直接 asset-clip、主视频无 lane、所有主字幕是原生 caption、字号标定为剪映 8 号、字幕使用 bottom 锚点且不存在 Final Cut Position 参数。

剪映正式草稿另运行：

```bash
python3 脚本/p4j_验收草稿.py <剪映草稿目录>
```

必须确认：`draft_info.json` 与 `draft_content.json` 一致；唯一视频轨的所有片段 `render_index=0`；字幕全部为原生 `subtitle`、字号 8、绑定剪映聚珍体资源；原素材路径有效。
