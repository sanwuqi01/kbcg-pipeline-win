# 口播视频剪映出草稿（Windows 版）

> **本版平台边界（移植声明）**
> - 运行环境：Windows + WorkBuddy 宿主。**不依赖 MLX、不依赖 zsh、不要求 Final Cut Pro。**
> - 交付分支：**只有剪映原生草稿**。`final-cut` / `both` 分支的代码（`p4f_*`、`finalize_fcp`）原样保留作对照，
>   但 Windows 宿主层**禁用**——用户选择 Final Cut 时必须停下并说明本版不支持，不得尝试生成 FCPXML。
> - 实机验收：剪映是桌面 Qt 应用，WorkBuddy 的浏览器自动化够不到 → 固定为**用户人工三查 + 截图作证**（见 P6）。
> - 本文件其余工序语义、契约、失败条件与 macOS 原版**完全一致**，不因平台而放宽。

> **宿主与模型约束（开工前必须确认）**
> 本版在 **WorkBuddy 桌面版** 上验证；会话模型用 **GLM 5.3 Flash 或 DeepSeek V4.1 Flash（二选一）**——
> 这是实测后的推荐档：性价比高、速度可接受（DeepSeek V4.1 Flash 于 2026-09-14 全链验证 EXIT=0）。
> 契约层（`脚本/`、`脚本_win/`、42 项契约测试）与模型无关，换谁跑都一样；
> 但**决策层**——`content_plan` / `keep` / `expression_review` / `structure` / `cards` / `cut_review`——
> 是模型给出的判断，不是代码算出来的。换宿主或换模型会让断句、口头语删留、开头选择整体漂移，
> **而 42 项契约测试仍然全绿，不会报警**。
> 开工前先确认这两项；不一致时必须**当场停下向用户说明**，不得静默按自己的判断开工，
> 也不得声称"已通过验证"。部署与逐台机器的适配步骤见 [`部署/安装说明.md`](部署/安装说明.md)。
> 钉死项的机读真值在 [`部署/环境契约.json`](部署/环境契约.json)。

> **两个入口，同一套工序（先读这段）**
>
> 本 Skill 有两条用法。**它们跑的是同一套 `脚本/` / `脚本_win/`、同一套契约、同一个工作区**，
> 不是两个版本，也不是二选一：
>
> | 入口 | 谁在跑 | 怎么用 |
> |---|---|---|
> | **剪辑工作台**（`剪辑工作台\`，在 WorkBuddy 工作区根目录——分发包解出的顶层文件夹下） | 状态机脚本：机械步骤全自动，六个判断闸口停下等人 | 视频丢 `剪辑工作台\输入\`，然后在对话里说「用口播出稿，跑一下输入」，由 AI 引导推进（**别双击 剪辑.cmd**——没有 AI 在场，没人审错误、没人盯闸口） |
> | **本文下面的工序**（P0 → P6，十七步） | 宿主 AI 逐步执行 | 在对话里说"用口播出稿，把这条剪一下" |
>
> **衔接点**：工作台只是把下面的步骤排成了状态机，并把这六个决策 JSON
> 「该在哪儿停下、该写什么字段」，抄了一份到 `剪辑工作台\说明书\工序与闸口.md`。所以——
> - 用工作台跑，**工序定义、字段要求、失败条件一律以本文为准**；说明书写得不一致时，按本文改说明书。
> - 用对话式跑，也可以借 `剪辑.py status` 查看自己走到第几步；产物在同一个 `工作区\<片名>\`。
> - 两条路径**可以来回切**：工作台停在某个闸口时，你也可以直接手写那个 JSON，再让工作台继续。
>
> 若 `剪辑工作台\` 不存在（只装了 Skill 本体），按本文走完整工序即可，**不因此停止**。

## 唯一生产原则

```text
P0 技术属性锁定
→ R 素材类型路由
→ P1 对应类型粗剪（内容、顺序、刀口）
→ F1 内部声学验收并冻结
→ P2 字幕文字与断句
→ P3 字幕声学对齐
→ P4 横/竖屏基础字幕样式
→ P5 授权范围内的其他包装
→ P6 Final Cut / 剪映交付
→ L 用户精调 XML 分层学习（有反馈时）
```

以上顺序写死，不得并行、倒序或把两层合并修。正常生产不设置“用户确认粗剪”闸门：P1 完成逐项表达裁决、独立音频验收与决策检查后，由 F1 在内部冻结并直接进入字幕和交付。除非用户明确只要粗剪，不导出粗剪审核版、不请用户先看粗剪、不停下等待“确认后继续”。人工粗剪 XML 等于从 F1 后进入；“只加字幕”执行 P2→P3→P4→P6，“继续完整包装”执行 P2→P3→P4→P5→P6。

粗剪决定“讲什么、为什么这样讲”；包装决定“这套论证怎样被看懂、记住并稳定交付”。包装可以新增字幕、标题、音乐、音效、调整层、局部画面处理和转场，但不得擅自改变冻结的口播字、声音、源时码、片段范围或顺序。发现内容问题必须退回粗剪、重审并重新冻结，不能用字幕、音乐、花字或 B-roll（补充画面）遮盖。

用户只要粗剪时，完成 F1 内部验收和粗剪锁后停止。其他请求默认直出最终可编辑工程：用户未说平台时，直接生成并登记剪映原生草稿箱最终版。完整工程仍必须先在内部完成粗剪和 F1，但不把这个内部质量闸门变成用户审核环节。Final Cut 与剪映共用同一份冻结粗剪和字幕时码，只在最后的工程结构与字幕载体上分支。

人工粗剪 XML 是独立入口。用户明确说“粗剪已完成，只加字幕”时，不再做内容判断、不重建粗剪、不修剪半词；只允许加字幕。用户明确说“在这个粗剪上继续包装”时，冻结口播内容，只新增包装层；为做缩放、定格或局部画面效果而拆开音视频时，口播音频的来源、范围、顺序和连续性仍不得改变。两个权限不能混用。详见 [`references/technical-delivery.md`](references/technical-delivery.md)。

## 问题只回到所属工序

每次用户反馈先归类，再修改。问题归属与允许修改面详见 [`references/stage-boundaries.md`](references/stage-boundaries.md)。硬边界如下：

- 选材、顺序、重复、口头语、刀口和尾音问题只回 P1；F1 重新验收冻结前不得进入字幕。
- 错字、漏字、基础字幕断句和语义关键词候选只改 P2；不得改粗剪源范围和顺序。P2 的 keyword 不等于成片上色。
- 字幕早出、晚出、段首空一两帧、换卡不贴发音问题只改 P3；不得改文字断点或样式。
- 字体、字号、颜色、X/Y 位置和横竖屏 profile 问题只改 P4；不得改粗剪、字幕文字或字幕时码。
- 音乐、音效、概念大字、调整层和转场问题只改 P5；不得反向污染 P1–P4。
- 文件格式、素材路径、DTD、Final Cut/剪映工程结构问题只改 P6。

修正前必须运行工序隔离锁，修正后必须验证；上游任一不变量漂移即失败：

```bat
"%PY%" "%BASE%\脚本\stage_scope_guard.py" begin <工作目录> <scope> [--force]
rem 只修当前 scope，再按既定顺序重生成下游产物
"%PY%" "%BASE%\脚本\stage_scope_guard.py" verify <工作目录>
```

## 支持与停止

- `single_speaker`：一份原文件中的中文单人口播、单人直播切片，支持从原素材开始的完整生产。
- `single_speaker_multi_source`：同一人、同一主题拆成多个原文件，内容方法仍读取“单人口播粗剪”；当前支持用户人工粗剪 XML 在原工程结构中加字幕，也支持已经通过验收的 `source_id` 冻结粗剪继续生成剪映草稿。新建 Final Cut 多 asset 终版仍停止。多个原文件直接交给 AI 从零粗剪时，只完成逐文件技术探测和素材关系报告后停止，不得把多个单源工作区临时拼接成伪多素材结果。
- `single_subject_interview`：一位学员是唯一内容主体，提问者原声全删。
- `multi_speaker`：可识别为双人/多人内容，但当前没有对应生产子技能与充足成对样本，停止而不是套用单人口播。
- 不能确认说话人数、不是上述支持类型、ASR（自动语音识别）与音频明显冲突、契约或验收失败时停止，不静默降级。

## 环境

### 首次运行自检（未初始化的工作区必须先装）

开工前先自检初始化状态，两条任一成立即视为**未初始化**，任何剪辑请求都不得直接开工：

- `%BASE%\.venv\Scripts\python.exe` 不存在；
- `模型\` 目录只有 `.gitkeep` 空壳（无模型实体）。

未初始化时的唯一安装路径是**对话式安装**——AI 替用户跑完整 bootstrap，全程不让用户碰命令行：

1. 告知用户：环境还没装，预计 10–30 分钟（主要在下载约 3.4 GB 模型），期间可以离开。
2. 用宿主工具**在后台**执行 `部署\bootstrap.py --yes`（工作目录 = 本 Skill 的 `部署\`），
   输出重定向到 UTF-8 日志文件再读（Windows 宿主控制台坑：pwsh 吞 stdout、GBK 乱码，
   详见 `剪辑工作台\说明书\AGENT运行守则.md` §1）。PowerShell 7 模板：

   ```powershell
   $env:PYTHONUTF8="1"; python -X utf8 bootstrap.py --yes 2>&1 | Out-File -Encoding utf8 bootstrap.log
   ```

   跑的是 `bootstrap.py`，**不是** `bootstrap.cmd`——`.cmd` 只留给用户双击/备用场景。
3. 轮询日志直到出现 `结论: ✅ 就绪`；中途失败按 [`部署/安装说明.md`](部署/安装说明.md) §6 故障排查表处理，
   处理不了就把日志最后几十行原样贴给用户。
4. 装完先跑自检 `"%PY%" "%BASE%\脚本_win\pipeline.py" doctor`，全 ✓ 再进入正常工序。

禁止事项：不得让用户自己开命令提示符跑 bootstrap；不得跳过 bootstrap 用系统 python 直接跑管线
（生产依赖不齐，GBK 控制台会在 emoji 处崩）；不得在未初始化时假装环境就绪开工。

新机器上的安装与逐项适配（含钉死版本清单）见 [`部署/安装说明.md`](部署/安装说明.md)；
装好后的自检入口：`"%PY%" "%BASE%\脚本_win\pipeline.py" doctor`。

**Windows 版（本版实际生效）**：

```bat
rem %PY% = 本机管线解释器。`脚本_win\pipeline.py` 会按这个顺序自动找（勿手工猜路径）：
rem   1. 环境变量 XGZ_PIPELINE_PY
rem   2. %BASE%\.venv\Scripts\python.exe                              ← 部署\bootstrap.cmd 默认建在这
rem   3. %USERPROFILE%\.workbuddy\binaries\python\envs\asr-win\Scripts\python.exe
rem 走 pipeline.py 入口时**不需要**自己 set；只有手工直调 脚本\*.py 才要。
set PY=%BASE%\.venv\Scripts\python.exe
```

`%PY%` 是**唯一的管线解释器**：转写、词轴、强制对齐、契约脚本全部用它 ——
macOS 原版的 PYMLX / PYALIGN / python3 三套路径在此收敛为一套。**唯一例外**是
`p4j_出剪映草稿.py`，它必须跑 CapCutMate 自己的 venv（由 `pipeline.py` 自动处理，不要手工改）。
所有入口（`pipeline.py`）会强制 `PYTHONUTF8=1`；**不要**用系统默认 `python` 直接调 `脚本/` 下的文件，
否则 GBK 控制台会在 emoji 输出处崩在半路。

**macOS 原版参考（本版不使用，仅供对照追溯）**：

```bash
PYMLX="$HOME/.local/share/uv/tools/mlx-whisper/bin/python"
PYALIGN="$HOME/.local/share/uv/tools/mlx-qwen3-asr/bin/python"
ASR_BIN="${MLX_WHISPER_BIN:-$HOME/.local/bin/mlx_whisper}"
```

公共生产依赖只有 `ffmpeg` / `ffprobe`、ASR 引擎、Silero VAD 与 Qwen3 ForcedAligner。
Windows 下：`ffmpeg`/`ffprobe` 须在 PATH（本机走 scoop shims，任何装法都行）；ASR 用 **faster-whisper**（CTranslate2，同款 `large-v3-turbo`
权重）；对齐器用 **transformers 原生 `qwen3_asr`** 加载 `Qwen/Qwen3-ForcedAligner-0.6B-hf`。
平台依赖检查按最终交付分支进行：

- **剪映原生草稿（本版唯一分支）**：需要剪映专业版已安装并**至少启动一次**，以及 CapCutMate；
  字幕字体是**可配置参数**（`p0_建工作区 --font <剪映字体名|资源id>`，默认「新青年体」，
  可选值见 `字体/剪映字体表.json`），通过剪映内置字体的**资源 id** 绑定，
  **不要求复制任何本机字体文件**（包括作者本机的试用字体）。
- Final Cut XML：**本版禁用**（代码保留）。用户明确要求该分支时停止并说明本版不支持。

缺少当前所选分支的生产依赖时停止；不得要求用户为未选择的平台安装软件。

## 准备

1. 先读取技术属性。新建工程必须保持原素材显示画幅、编码画幅、旋转、真实帧率、音频采样率与声道；不转码、不缩放、不裁切。多素材属性不一致时停止，不自动统一。若输入是多个原文件，先按 `material-routing.md` 判断是否已有人工 XML 或 source-aware（逐素材标识）冻结粗剪；没有时不得分别运行多个单源 P0/P1 后再拼接。

2. 建工作区。内部片名可保留技术编号；最终交付名必须包含当天日期和中文核心表达。

```bat
"%PY%" "%BASE%\脚本\p0_建工作区.py" <视频路径> [内部片名] --material-type single_speaker --core-expression <中文核心表达>
```

课程好评采访改用 `--material-type single_subject_interview`。核心表达尚未确定时可暂不填，但粗剪冻结前必须补齐。
`--color-reference-xml` 是 Final Cut 分支专用的色彩兜底参数，**Windows 版不用**（剪映原生草稿不受色彩三元组影响）。
一键等价命令：`"%PY%" "%BASE%\脚本_win\pipeline.py" p0 <视频路径> ...`（建工作区后直接接转写）。

3. 转写。**Windows 版不要用 `mlx_whisper`**（Apple 专属）。用项目内的 faster-whisper 适配器：

```bat
"%PY%" "%BASE%\脚本_win\转写_faster_whisper.py" <视频路径> --outdir <工作目录> [--hotwords "你的IP名,机构名,领域术语"]
```

`--hotwords`（空格或逗号分隔）用于预防 IP 专名与领域术语的同音错字
（实测案例：IP 人名曾被听成同音字；走剪辑工作台时在 `配置\设置.json` 的
「转写热词」里填一次即自动透传）。下游 `核专名.py` 只做事后候选，不替代热词前置。

该适配器的参数已**逐项对齐 macOS 原版基线**，不要手工改：
`language=zh`、`condition_on_previous_text=False`、`beam_size=1`（对齐 mlx 的贪心默认）、
`vad_filter=False`（**架构级**：`p1a` 靠自己的 silero-vad 把真实停顿暴露成 gap；转写阶段先滤静音会让词轴重排、停顿永久丢失）、
`word_timestamps=True`、模型 `large-v3-turbo`（local_dir 实体目录，不走 HF symlink 缓存）。

工作目录必须且只能有一份非 aligned 的 `*_words.json`。

## 阶段一：粗剪

### 1. 先决定内容

先通看全素材，再写 `content_plan.json`：目标、受众、核心主张、覆盖全词轴的主题地图、开头候选、选中开头、当前主线和样本证据。主题块内仍必须按句级信息增量过一遍：每个保留单元都要能说明它新增了信息、证据、情绪、信任或必要承接中的至少一项；章节判断已完成后的弱复述、感叹或重新报幕应删除。但设问、步骤起句和改变命题的自我修正必须先做“删后依赖”检查，不能只因词面重复就删。现有字段名 `hook_candidates/selected_hook` 为兼容工程保留，但允许 `hook_type=natural_premise`（自然前提）；不得因为字段名叫 Hook 就强造爆点。JSON 只记录已经完成的编辑判断，不能代替判断。

`single_speaker` 先读“单人口播粗剪”，再决定哪一遍表达承担主线；不要把不同素材编号机械串联，也不要为了爆点而牺牲一个完整、可信、可自然兑现的开头。

学员好评先按采访方法说明清楚：课程价值、目标人群、候选主题、选中片段、开头理由、正文顺序和未选内容。多条输出必须先建立一份 `portfolio_plan.json`，按不同观众问题和核心证明拆题；条数来自用户授权，每个工作目录只做其中一条。跨片复用必须逐段说明不同功能和不可替代原因。

### 2. 决定原声留删

写 `keep.json`：

- `drop`：删除声音；
- `fix`：只修 ASR 文本；
- `retain`：记录有意保留的口头语、犹豫、强调或自我修正；
- `split_after`：两侧声音都保留，但明确建立结构边界。

刀口只用于真实删减、停顿压缩、重排或明确 `split_after`；不得为了段长参考值额外加刀。
每段头部先保住第一个字的辅音起音和气口，默认从真实起音前预留约 2 帧；
每段尾部以“词轴末尾”和“真实声学衰减尾”中更晚者为起点，再默认留约 11 帧安静余量。
两个目标都必须被前方已删声音、下一发音/drop 起点或素材边界钳住；余量不足必须记录安全上界并听审，不得为达数字包回被删声音。

不按词表机械删“呃、嗯、呢、啊、这个、就是”。判断删后是否更完整自然，以及它是否承担思考、强调、语气、情绪、命题修正或承接功能。词表只负责发现容易漏审的候选；每一项必须听原音后明确写成 `drop / retain / not_micro`。自我修正若改变最终命题，必须保留最终修正链或完整重构，不能按废话删除。用 `脚本/查词.py` 查下标，用 `脚本/核专名.py` 查英文缩写与专名。

采访还必须先写覆盖全词轴的 `speaker_turns.json`，并把所有提问者词放入 `drop`。依赖已删除问句的“对、是的、这个”等残句不能靠字幕伪造语境。

```bat
"%PY%" "%BASE%\脚本\decision_contract.py" validate-keep <工作目录>
"%PY%" "%BASE%\脚本\p1a2_对齐词轴.py" <工作目录>
"%PY%" "%BASE%\脚本\p1a3_字缝吸附.py" <工作目录>
"%PY%" "%BASE%\脚本\p1c_生成表达审查.py" <工作目录>
"%PY%" "%BASE%\脚本\p1_建段.py" <工作目录>
```

**字缝吸附（`p1a3`）不可跳过。** 强制对齐器给的是「这个字大致落在哪一段」，不是
「声学字缝在哪个采样点」——停顿处两者一致，**连读处会偏 55–190ms**。实测（2026-09-14
人工抽听）：`第三步` 的「三」被标成 `24.880-25.200`，而 24.880 处仍在发声，
刀口切在前一个字「第」内部 → 用户从那段里听到「第三」两个字；「第」只分到 80ms
（常速单字 150–250ms）。全片扫描 112 条字缝有 **33 条偏 55–190ms**，人耳可察觉
门槛约 70–80ms。`p1a3` 是纯后处理（不重跑模型），把字缝挪到能量谷中心，
并把词级 `ws/we/vs/ve` 与 `blk` 按 p1a2 同一套规则重推。它**必须在 `p1a2` 之后、
`p1c` / `p1` 之前** —— `p1c` 绑定 `word_track` 哈希，`segments.json` 会整份抄走
`char_times`，顺序错了这两处就全废。审计报告 `char_snap_report.json` 逐条记下
每次位移的起止与谷深，可复核。

`expression_review.json` 必须逐项填写；生成器同时给出 `expression_review.填写示例.json`，示例只说明字段含义，不是当前素材的决定。`micro_candidates` 的词表不产生自动删留；`residual_candidates` 是 VAD 检出的词轴外残声，必须听审为 `filler_drop / breath_noise / restore_text`。`pause_candidates` 是相邻保留词之间的停顿候选：发现门槛只负责提醒，绝不自动下刀；只有听审为 `ineffective_wait + compress` 才压缩，思考、强调、情绪、转折、动作、呼吸或句间功能必须 `retain`。不再使用“超过某个秒数一律删”的全局规则。若是有意义漏字，先修回词轴并重跑对齐与表达审查；不得靠隐藏字幕或自然排除带病进入冻结。表达审查同时绑定 `word_track` 和 `keep` 哈希；任一上下文变化都必须重审，不得按旧下标沿用决定。

用户明确要求一份粗剪 XML，或需要建立“AI 初稿—用户精调”学习对时，可以在冻结后额外生成一份

只有通过粗剪锁，阶段一才结束。修改任何被锁决策后都必须重审并 `freeze --force`。

## 阶段二：字幕、包装与平台交付

进入条件：粗剪锁有效，且用户要求继续包装。先确认范围：`只加字幕`、`字幕+指定组件` 或 `完整包装`。授权范围不清时只完成基础字幕，不自行添加音乐、音效或视觉效果。

### P2. 建立字幕文字真值

此时才写 `cards.json`：按句法与意群断句，字符级声学时码决定切换时刻；不拆词、
不按字数机械切、不隐藏仍在播放的声音。基础字幕保持单行，过长时在新谓语、宾语、
转折、状语收束或新意群之前换成下一张连续字幕卡，不在卡内硬换行。当前横版机器护栏
为 13 个全角字宽、竖版为 10；护栏只负责拒绝过长卡，不能替 Agent 自动均分句子。
视频切口与字幕断点可以用字幕桥接解耦，但每个字仍归属真实发音片段。

基础字幕是口播真值层；开场命题、概念大字、人物口吻提示和编辑批注属于包装标题层。两层可以同时出现，但包装文字不得写回 ASR、`keep.fix` 或基础字幕来伪造说话内容。`cards.json`/`captions_plan.json` 里的 keyword 只是 P5 可选候选，禁止在 P2 全部上色。

断句还有一条机器硬门槛：不得在 ASR 已确认的多字词或英文 token 内部切卡。诸如
“账号、视频号、方法论、ALL IN、INTJ”必须作为原子单位；语义 Agent 即使认为字数更匀，
也无权覆盖这个边界。断点先过 `caption_boundary_contract.py`，再做语义审阅。

注意 contract 的盲区：ASR 词轴按字切分，医疗/领域术语（白带、卵泡、雌激素、厘米…）
在词轴里是多个独立单字，contract 的不可拆单元管不到它们——机械分卡会把术语切在
卡界（2026-09-29 医生口播实测：「…是好白|带呢」）。`cards.json` 写完、p3 投影前
必须跑 `脚本/核断点.py <工作目录>`：查术语切界、「的/是」悬尾、单字孤卡三类候选；
只列不判，逐条按意群重切到干净。句末语气词（了/呢/啊）收尾是正常句界不算问题。用户精调
XML 中已经逐卡确认的前缀属于更高优先级真值：续写后半段时必须锁住该前缀的文本、
顺序和起点，写入哈希回归锁；Final Cut 与剪映交付都不得重新分卡或二次平移。

### P3. 独立完成字幕对齐

`cards.json` 一旦确认，P3 只把既定卡片投影到 `captions_plan.json`，不重新断句。段首与段内换卡分开：每个保留视频段的首卡必须从该段第一帧开始，不能因 VAD（语音活动检测）或首字时码留下 1–2 帧空洞；段内换卡取下一卡首字的字符级起音，只有它仍在静音且半秒内真实开口时才允许向后钳制。每段末卡覆盖到片段末尾，卡间不留空洞。每张卡必须同时保存 `local_sf/local_ef`（段内锚）与 `source_sf/source_ef`（原素材锚），并与时间线帧三向守恒。
Final Cut XML 和剪映草稿必须共用同一份 `rough_segments.json` 与 `captions_plan.json`：剪映序列化使用“归属视频段 target 起点 + 段内声学偏移”，段首/段尾与视频边界硬吸附；禁止两个平台各做一次粗剪/分卡决策，也禁止用整条绝对时码二次换算产生取整漂移。

### P4. 独立套用横/竖屏基础字幕样式

样式只在 P3 时码确认后套用，不参与修字、断句或对齐。分支数值互不借用：Final Cut 的 1080×1920 是聚珍体 50 / X=0 / Y=-220，3840×2160 是 120 / X=0 / Y=-478.53，2160×3840 是 52 / X=0 / Y=-190，并开启黑色投影（不透明度 75% / 模糊 0.63 / 距离 2 / 角度 315°）；剪映原生草稿的 1080×1920 与 2160×3840 都使用剪映聚珍体 14 / X=0 / `transform.y=-0.3791667` /基础色纯白 `#FFFFFF`，3840×2160 剪映样式独立为 8 / X=0 / `transform.y=-0.72` /纯白。2160×3840 剪映 profile 已由用户人工确认，生产时直接使用，不再要求用户重复确认；它不是把 Final Cut 的 52 号线性换算过去。画幅 profile 必须逐一登记，不得在运行时临时按像素倍数推导。Final Cut 真相源仍是 `media_contract.caption_profile()`；剪映只读 `jianying_contract.caption_profile()`。

概念大字、开场命题和编辑批注不属于基础字幕 profile，必须放在 P5 的独立职责中；不能用它们的字号或位置反推 P4。

### P5. 按语义章节做其他包装

仅在用户授权完整包装或指定组件时，按 R 的素材类型读取对应包装子技能，先把成片分成实际语义章节，再决定哪里需要强化。包装密度不平均分配：只在章节启动、概念转折、证据出现、包袱落点或方法收束处增加层次。

剪映重点上色必须另写 `jianying_packaging.json`，逐卡登记 `si + card_index + text + keyword + reason`。只升级开头利益、章节命题、方法揭示、关键对比和结论卡；总数不得超过基础字幕的 6%。没有显式清单时宁可全部纯白，不得把 P2 keyword 候选全部上色。

Final Cut 的重点上色与顶部标题也必须另写 `final_cut_packaging.json`；P2 的 keyword 和 `captions_plan.title` 都只是候选，不能直接变成成片包装。没有该清单时，`p4f` 只生成纯白基础字幕，不生成重点色或顶部标题。音乐、音效、概念大字、调整层、局部画面和转场是否已自动表达，按 [`references/packaging-capability.md`](references/packaging-capability.md) 逐项声明；任一已授权组件没有可验证实现时，只能报告“待人工补齐”，不得把基础交付冒充完整包装。

执行顺序固定为：全局画面基线 → 局部画面强调 → 对白响度与清晰度 → 章节音乐 → 论证型声音证据 → 节点音效 → 淡入淡出和混音复核。说话人提到一种可识别声音时，实际声音可以作为论据；它与装饰音效必须分开判断。任何视觉处理需要拆分视频和音频时，先保护冻结对白，再处理画面。

### P6. 平台交付

先判断用户最终在哪个软件继续剪辑。**Windows 版只支持剪映**：用户明确要 XML/Final Cut 时必须停下并说明本版不支持（`final-cut` / `both` 的代码保留作对照，宿主层禁用）：

```bat
rem 剪映（本版唯一可用分支）
"%PY%" "%BASE%\脚本_win\pipeline.py" finalize <工作目录> jianying
```

> `f1` 步骤同理走 `pipeline.py f1 <工作目录> [--force]`（等价 `f1_粗剪验收冻结.sh`）。
> **`f1` 报"决策锁已存在"不是 bug** —— 契约禁止静默覆盖既有 `decision_lock.json`，需显式传 `--force`。

平台分支只发生在最终序列化：

- `final-cut`：**Windows 版禁用**。代码（`p4f_出FCPXML.py`）原样保留作对照，但不得在 Windows 上执行；用户要求时停下说明。
- `jianying`：正式产物只是 `_剪映草稿`。素材库按冻结粗剪实际引用集，每个源文件只登记一份完整原片；单源是一份，多源必须按 `source_id` 逐段映射。视频片段全部写入 `render_index=0`真实主轨；字幕是原生 `subtitle`，并从剪映独立精确画幅 profile 读取字号、纯白色和 X/Y，不再全局写死“8 号”。每张字幕时码以归属视频段为锚，验收时禁止越过视频切点。
- 剪映序列化前必须运行 `p4j_准备交付素材.py`。原片在 Downloads、Desktop、Documents、临时附件目录、移动硬盘或网络卷时，默认建立 SHA-256 一致的受管副本，不移动、不转码原片。用户显式选择 `reference_original` 时可保留原路径，但实机验收前必须标记权限风险。
- 剪映草稿根不得写死为 `~/Movies/JianyingPro/...`。交付前必须运行 `p4j_定位剪映草稿根.py`：显式 `JIANYING_DRAFT_ROOT` 优先，其次识别正在运行的剪映、剪映实际初始化的 `root_meta_info.json`、最近活动路径和已保存配置。剪映数据位置变化后要自动切到新草稿根；多路径仍无法唯一确定时停止并要求用户打开剪映新建一个空白草稿，不得向可疑旧目录密写。
- **Windows 版特有：索引与草稿实体是分离的**。索引固定为
  `%LOCALAPPDATA%\JianyingPro\User Data\Projects\com.lveditor.draft\root_meta_info.json`，
  草稿实体在剪映 `Config\globalSetting` 的 `[General] currentCustomDraftPath` 声明的位置
  （实测本机为 `D:\JianyingPro Drafts`）。**两者不同目录，不要混用**：
  写草稿用实体路径；登记草稿箱必须另传 `--root-meta <索引路径>`。
  定位器要返回**两个**路径，`--list` 输出已含 `root_meta_index` / `declared_custom_root` 两字段。
- 草稿根定位必须区分 `not_initialized / invalid_meta / current_process_read_denied / current_process_write_denied / ready`。找到有效索引但当前进程不可写时，要求系统权限，不得误导用户重新建空白草稿。
- `p4j_验收草稿.py` 只能产生 `complete_structural`：它证明 JSON、素材路径/哈希、主轨、字幕和样式结构正确，不证明剪映界面已显示项目素材，也不证明剪映进程能读原片。
- `finalize jianying` 返回后必须继续打开新草稿做实机验收：左上角项目素材可见、时间线无“无访问权限”、播放器可出画面。
  **Windows 版固定走人工通道**：剪映是桌面 Qt 应用，宿主只能做浏览器自动化、够不到它，因此
  **由用户在自己已登录的剪映里打开草稿做三查，并回一句确认或丢一张截图作证**，然后 agent 运行
  `p4j_记录剪映实机验收.py` 写入记录。三项全部为真才能写 `complete_runtime_verified`；
  否则必须写 `relink_required` 或 `material_bin_failed`。
  **不得**因为"没有 Computer Use"就把 `complete_structural` 直接升格成完成。
- 实机检查出现“链接媒体”、“无访问权限”或项目素材为空时，先读 `media_delivery.json.sources[].delivery_path`，再通过剪映自己的“链接媒体/导入”界面选择该路径（Windows 下用剪映的"重新链接/导入"对话框）；不得伪造授权标记或仅改 JSON 冒充授权。链接/导入后重新检查三项并更新实机记录；无法完成界面操作时才把一次人工链接作为唯一待办交给用户。
- 实测剪映会把合法 FCPXML 的主故事线统一导到封面上一层，并额外生成空主轨。因此不得再把“FCPXML spine 正确”报告成“剪映界面真实主轨正确”；需要真主轨时必须交付原生草稿。
- 剪映草稿名固定带 `_剪映草稿`，防止与 Final Cut 文件混用。不得把 Final Cut XML 改名后冒充剪映版。

两个基础终结器都只执行：锁验证 → 字幕投影 → 帧级验收 → 平台工程生成 → 结构终检 → 中文日期命名交付。不得重跑转写、建段或结构编排。完整包装若尚未被当前终结器表达，必须在其输出上追加非破坏性包装层，并重新做 DTD、核心对白覆盖、混音和视觉复核；不得把“基础字幕 XML 已通过”报告成“完整包装已通过”。只有 Final Cut 分支会尝试交给“字幕校对”FCP 工作流程扩展；剪映分支不调用该面板。

横屏与竖屏都按原素材画幅交付；1080p 与 4K 分别使用当前精确画幅已确认的独立字幕 profile，绝不缩放视频，也不线性缩放字幕参数。任何未确认画幅都必须停止。剪映原生草稿承诺封面同级真主轨、精确画幅原生字幕、聚珍体、纯白基础字和统一调整能力。基础字幕 profile 不能被概念大字或编辑批注反向改写。

## 不能绕过的失败条件

- 内容地图没有覆盖全词轴，当前片同时选择多条主线，或多条组合计划与当前工作区不一致。
- 样本类型、路径或哈希不符；把开发案例、同源多条或污染基线冒充独立运行样本。
- 提问者漏删，`candidate/exclude` 内容仍进入当前片，留删区间冲突或越界。
- 结构漏段、未登记重复、Hook 未在开头、倒序无理由，或改变原声文本/源时码。
- 真实切口未逐个听审，词头、尾音、呼吸或删词残留存在疑点。
- 字幕与保留声音不等、缺字符级时码、用线性估时或隐藏字幕兜底。
- 用户只反馈某一工序，却修改了该工序的上游不变量；没有通过 `stage_scope_guard.py verify`。
- 把字幕文字、声学对齐和基础样式合成一次“整体调字幕”，导致改 Y 轴时重切字幕，或改对齐时重做粗剪。
- 新建工程的画幅、帧率、旋转、素材引用或音频属性与原素材不一致；多素材属性冲突却被静默统一。
- 人工 XML 的非字幕结构、项目属性、素材资源或任一视频段发生变化。
- 只加字幕权限下出现音乐、音效、调整层、转场或非字幕标题；完整包装权限下改变冻结对白的来源、范围、顺序或连续性。
- 把开场标题、概念大字、拟声文字或编辑批注混入基础字幕/ASR 真值；为填满时间线而平均铺设包装节点。
- 对白未先保证可懂度就叠加音乐与音效，或论证型声音素材没有明确对应说话内容。
- 交付平台未按需求选择；未说明时没有走剪映原生草稿；剪映正式草稿的素材库与冻结粗剪实际引用集不等，同一原片重复登记，多源片段没有按 `source_id` 对应，视频片段不全在 render_index=0 真主轨，字幕不是 subtitle、未命中当前剪映精确画幅 profile，未绑定聚珍体资源，或字幕越过视频切点。
- 剪映分支把 `complete_structural` 当成最终完成，未检查项目素材可见性、时间线媒体权限和播放器画面，或在 `relink_required / material_bin_failed` 状态下宣称已完成。
- **Windows 版专属**：在 Windows 上执行 `final-cut` / `both` 分支、生成 FCPXML 并宣称"Final Cut 可用"；或把 Windows 上的「剪映索引目录」当成草稿实体目录去写草稿（Windows 上两者分离）。
- F1 内部声学验收未通过或粗剪未冻结就包装，锁哈希漂移，DTD 缺失或任一验收失败。
  （Windows 版不产出 FCPXML，故 DTD 项不适用；其余全部适用。）

## 交付报告

分别报告：

1. 内容方法：核心表达、课程/主题价值、受众、选材、开头、排序和删除理由；
2. 粗剪执行：时长、留删/修正/有意保留、真实切口、重排、Hook、听审和锁状态；
3. 包装验证：仅在实际进入阶段二时，按实际范围分别报告字幕真值、视觉层级、对白/音乐/音效、核心对白保持、DTD、文件与哈希；
4. 证据边界：技术通过、Agent 内部验收和用户事后精调反馈必须分开表述。

剪映交付报告还必须单独报告 `delivery_state`、原片/受管路径、结构验收和实机验收证据。`complete_structural` 只能说“工程结构已生成”，不能说“剪映交付完成”。

用户在 AI XML 上精调后，按 `references/feedback-learning.md` 运行 L：锁定两版哈希、生成 P0–P6 分层差异，再结合原音解释。只把实际差异更新到对应粗剪、字幕、对齐、样式、包装或交付规则；不得改动无关工序，也不得把同一素材的新修订计为新的独立证据家族。用户只有口头评价而没有精调文件时，只记录评价实际覆盖的范围，不把一句整体认可拆成“每个刀口、每张字幕卡、每项包装均被逐项确认”。

只陈述可验证结果；没有经过新素材前向测试时，不承诺“完全一致、百分百学会或绝不返工”。
